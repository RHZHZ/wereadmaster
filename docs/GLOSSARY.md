## 使用规则

1. 页面标题、导航、按钮、toast、空态、用户指南和现行设计文档使用同一规范词。
2. 内部命令名、缓存 feature、数据库字段和协议 key 不因 UI 术语治理被机械改名；协议迁移必须另行设计。
3. 新增产品名词前先更新 `src/lib/glossary-data.json`，再由 TypeScript 门面和检查器共同消费，不在多个运行时重复维护词表。
4. E2E 优先使用稳定 `data-testid` 定位关键入口，再单独断言规范文案；不要把大段中文文案当作唯一定位依据。
5. 历史发布说明、归档审计或被取代文档可以保留当时用语，但必须有明确文档状态；受管现行文档不得依赖整文件豁免。
6. 检查器豁免只能精确到“相对文件 + 词”，且需要解释；禁止整目录、通配符或整文档放行。

## 阅读阶段边界

阅读阶段使用以下统一口径：

- 69%：深入推进。
- 70%、95%、99%：收束整理。
- 100% 或 `finished=true`：完成归档。

生产计算、边界测试与现行文档必须保持一致。
