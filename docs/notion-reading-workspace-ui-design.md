# Notion 阅读工作台 UI 设计文档

## 1. 设计结论

当前 Notion 首页的问题不是字段不足，而是页面像一篇线性说明文：

- 首屏缺少工作台定位。
- 信息入口没有视觉分区。
- 数据库链接不够突出。
- 用户不知道导入后下一步该做什么。
- 五类成果的价值没有形成“可点击、可整理、可行动”的前端体验。

新模板应从“说明页”升级为“阅读成果工作台”：

> 首页负责引导和分流，数据库负责承接成果，成果页负责保存完整内容。

首版仍保持一个首页 + 一个核心数据库，不拆多库关系，不做复杂同步。UI 的重点是通过 Notion 稳定 block 组合，做出清晰、有层次、可持续使用的前端。

## 2. 设计目标

- 首屏 10 秒内让用户理解：这里是微信读书成果中转站。
- 页面入口要比说明文字更突出。
- 用户可以按成果类型、整理状态、行动项找到内容。
- 结构必须能由 Notion API 稳定创建。
- 模板既适合第一次使用，也适合长期反复导入。

## 3. 非目标

- 不做双向同步 UI。
- 不自动更新已有 Notion 页面。
- 不创建多数据库关系系统。
- 不依赖 Notion 复杂 linked database 视图自动初始化。
- 不把 Notion 页面做成任务管理系统。

## 4. 视觉方向

关键词：

- 阅读资产
- 知识工作台
- 温暖、克制、清晰
- 比普通文档更有入口感
- 比复杂模板更轻、更稳定

视觉策略：

- 使用封面图建立第一印象。
- 使用 icon 和 callout 背景色制造模块感。
- 用短句替代长段说明。
- 用 toggle 收纳说明，避免页面过长。
- 用 bookmark block 突出核心数据库入口。
- 用 checklist 表达导入后的整理动作。

## 6. 首屏设计

### 6.1 Hero

使用蓝色背景 callout。

文案：

```text
阅读资产工作台：把微信读书里的划线、想法、AI 复盘、阅读路线和选书决策，沉淀成一个可整理、可检索、可行动的长期知识库。
```

图标：

```text
🧭
```

设计理由：

- 直接说明页面价值。
- 不再使用“由 wxreadmaster 自动创建”作为第一句话。
- “可整理、可检索、可行动”对应 Notion 的核心使用场景。

### 6.2 边界说明

使用 quote block，降低视觉重量。

文案：

```text
边界说明：这里是一键导出/导入工作台，不是双向同步。每次导出都会创建新的成果页，方便保留版本历史。
```

设计理由：

- 避免用户误解成实时同步。
- 放在首屏，但不抢 Hero 注意力。

## 7. 今日驾驶舱

使用三个 callout，形成类似仪表盘的入口。

### 7.1 最近导入

- Icon：`🕘`
- Color：`gray_background`
- 文案：`最近导入：打开阅读成果库后，按导出时间倒序查看最新成果。`

### 7.2 待读整理

- Icon：`🧺`
- Color：`yellow_background`
- 文案：`待读整理：把导入状态改为待整理，形成 Notion 内部整理队列。`

### 7.3 行动优先

- Icon：`🎯`
- Color：`green_background`
- 文案：`行动优先：筛选行动数大于 0 的复盘、阅读路线和选书决策。`

设计理由：

- 让首页从“说明”变成“下一步入口”。
- 即使 API 暂不创建复杂过滤视图，也能明确告诉用户怎么组织视图。

## 8. 成果入口

五类成果用五个 callout 表达，避免普通 bullet list 的廉价感。

| 成果 | Icon | Color | UI 文案 |
| --- | --- | --- | --- |
| 书籍笔记 | `📒` | `green_background` | 保存原始划线、想法、章节分组和封面，是所有复盘的证据层。 |
| 书籍复盘 | `🧠` | `blue_background` | 沉淀概览、主题标签、关键观点、行动项和复盘问题。 |
| 阅读路线 | `🗺️` | `orange_background` | 记录当前书、候选书、推进顺序、检查点和下一步行动。 |
| 统计复盘 | `📈` | `yellow_background` | 按周、月、年或总览回看阅读节奏、偏好和阶段变化。 |
| 选书决策 | `🧩` | `purple_background` | 保留下一本书的选择依据、取舍、预计投入和触发条件。 |

设计理由：

- 这五类正好对应当前应用可导出的成果。
- 使用不同颜色帮助用户建立记忆。
- 不额外创建五个数据库，避免过度设计。

## 9. 核心数据库区域

### 9.1 数据库定位

使用蓝色背景 callout。

文案：

```text
阅读成果库是这个工作台的唯一核心表。每一次导出是一条成果记录，正文保留完整内容，属性用于筛选、排序和整理。
```

### 9.2 数据库入口

使用 bookmark block 展示数据库 URL。

备用使用 paragraph link：

```text
也可以从这里打开阅读成果库
```

设计理由：

- bookmark 比普通链接更像入口卡片。
- paragraph link 作为兼容兜底，避免 bookmark 渲染失败时入口不明显。

## 10. 推荐视图配方

Notion API 首版不强依赖自动创建 linked database 视图，因此使用 toggle block 提供视图配方。

### 10.1 全部成果

- 过滤：无。
- 排序：导出时间倒序。
- 用途：作为最近导入和全局检索入口。

### 10.2 五类成果视图

- 过滤：资产类型分别等于对应成果类型。
- 排序：导出时间倒序，或按导入状态分组。
- 用途：让不同阅读成果拥有独立入口，但仍共用一个数据库。

### 10.3 待读整理

- 过滤：导入状态等于待整理。
- 排序：行动数倒序，再按导出时间倒序。
- 用途：把导入后的二次加工变成一个稳定队列。

设计理由：

- toggle 收纳说明，页面不显得啰嗦。
- 用户可以按说明手动创建视图。
- 后续如果 Notion API 视图能力稳定，再把这些配方升级为自动创建。

## 11. 整理工作流

使用 unchecked to-do blocks。

```text
[ ] 导出后先检查标题、资产类型、导出时间和导入状态。
[ ] 优先处理行动数大于 0 的书籍复盘、阅读路线和选书决策。
[ ] 整理完成后把导入状态改为已复盘或已归档。
```

设计理由：

- 比编号列表更有“工作台待办”感觉。
- 用户可以直接勾选，不需要理解复杂方法论。

## 12. 字段速览

使用两个 callout。

### 12.1 核心字段

```text
核心字段：名称、作者、资产类型、导出时间、导入状态、标签、微信读书、Obsidian 路径、Prompt 版本、输入哈希。
```

### 12.2 兼容说明

```text
建议保留字段名不变。wxreadmaster 会只写入存在且类型匹配的属性；如果你删掉某个字段，正文导入仍会继续。
```

设计理由：

- 给高级用户足够的可维护边界。
- 降低用户改字段后导入失败的恐惧。

## 13. Notion API 可实现性

首版使用这些稳定 block：

- `heading_2`
- `heading_3`
- `paragraph`
- `callout`
- `quote`
- `divider`
- `bookmark`
- `toggle`
- `to_do`
- `bulleted_list_item`
- `numbered_list_item`

不使用这些作为 P0 强依赖：

- 自动创建复杂 linked database 视图。
- 自动创建按钮模板。
- 多数据库 relation / rollup。
- 数据库模板页面。
- 图表和公式仪表盘。

原因：

- P0 目标是稳定一键创建。
- Notion API 能力和版本变动会影响复杂模板。
- 当前应用导出的完整载体仍是成果页正文，不是结构化任务系统。

## 14. 数据库字段设计

核心数据库继续使用 `阅读成果库`。

字段分组：

| 分组 | 字段 |
| --- | --- |
| 基础定位 | `名称`、`作者`、`Book ID`、`Scope ID` |
| 导入管理 | `资产类型`、`来源`、`导出时间`、`导入状态`、`阅读状态` |
| 阅读结构 | `阅读阶段`、`进度`、`标签`、`周期` |
| 外部链接 | `微信读书`、`Obsidian 路径` |
| AI 追踪 | `Prompt 版本`、`输入哈希` |
| 数量统计 | `行动数`、`候选书数`、`划线数`、`想法数`、`书签数`、`可导出数` |

写入规则：

- 只写存在且类型匹配的字段。
- `微信读书` 只对真实 `bookId` 或显式 `wereadUrl` 写入。
- 双目标导出成功写入 Obsidian 时，Notion 记录 `Obsidian 路径`。
- 字段缺失不阻断正文导入。

## 15. 应用内设置页预览建议

当前设置页的 Notion 预览也应跟随真实模板升级。

建议展示：

```text
Notion 阅读工作台
  Hero：阅读资产工作台
  今日驾驶舱：最近导入 / 待读整理 / 行动优先
  成果入口：笔记 / 复盘 / 路线 / 统计 / 决策
  核心数据库：阅读成果库
```

交互策略：

- 主路径：`使用推荐 Notion 模板`，用户复制模板后，应用在模板首页下创建并绑定 `阅读成果库`。
- 兜底路径：`没有模板？创建基础 Notion 工作台`，创建首页 + 阅读成果库。
- 高级入口：`已有数据库？手动配置目标 ID`。

理由：用户可以优先获得成熟的书架和仪表盘体验；基础工作台保留为不依赖第三方模板的可控兜底，而不是默认视觉方案。

## 16. 验收标准

- 首页不再像纯说明文档。
- 首屏能看到工作台价值、边界和下一步入口。
- `阅读成果库` 入口明显。
- 五类成果都有独立视觉入口。
- 整理动作以 checklist 呈现。
- 推荐视图以 toggle 收纳，不堆满页面。
- 模板仍然只创建一个核心数据库。
- 现有 Notion 导入字段写入逻辑不回退。
- Obsidian 与 Notion 双目标导出不产生同步冲突。

## 17. 后续增强

P1：

- 创建完成后提供“复制推荐视图配方”按钮。
- 为官方文档增加截图版教程。

P2：

- 评估 Notion 新版 data source / 视图 API 后，再自动创建过滤视图。
- 如果用户强需求出现，再拆分 `书籍库`、`成果库`、`行动库` 三库结构。
