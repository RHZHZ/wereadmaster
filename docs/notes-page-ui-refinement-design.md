# 笔记中心 UI 层级与空状态优化设计文档

## 1. 文档信息

- 适用页面：`NotesPage`
- 实现入口：`src/pages/NotesPage.tsx`
- 样式入口：`src/styles.css`
- 设计范围：笔记中心，不包含单本书笔记正文页
- 设计阶段：P0 体验优化方案
- 目标主题：浅色、深色、紧凑密度

## 2. 背景

当前笔记中心已具备完整的业务能力：凭据引导、笔记同步、统计概览、建议复盘、书籍搜索、书籍卡片浏览、批量导出及多类异常状态。

页面功能没有明显缺失，但从截图和当前实现看，信息层级仍偏“功能平铺”：

- 页面主标题使用“划线、想法和书签数量”，更像统计模块标题，不能准确表达页面任务。
- `同步笔记` 与 `批量导出` 使用相同按钮样式，主次操作不明确。
- 空状态虽然已有同步入口，但主动作使用弱化样式，用户仍需判断下一步。
- 五项统计、建议复盘、搜索和书籍列表连续出现，首屏内容主次不够稳定。
- 宽屏下内容容易横向伸展，窄内容场景则会产生明显空白，视觉重心不够集中。
- 多个区域都采用完整卡片容器，容易形成同质卡片堆叠，削弱阅读节奏。

本次不推翻现有页面结构，而是以当前工程实现为基线，优化标题、操作优先级、状态呈现、内容节奏和响应式布局。

## 3. 设计上下文与假设

项目尚未形成独立的设计上下文文件。本方案先基于产品现状采用以下假设，后续如补充正式品牌规范，应以正式规范为准。

### 3.1 目标用户

- 使用微信读书并希望集中管理划线、想法和书签的个人用户。
- 主要在桌面端进行笔记整理、回顾和批量导出。
- 用户可能拥有数十到数百本带笔记的书，需要快速定位目标书籍。

### 3.2 核心任务

按优先级排序：

1. 确认笔记是否已同步，并在必要时执行同步。
2. 找到一本书并进入单本书笔记页。
3. 查看笔记规模和内容构成。
4. 发现值得继续复盘的书。
5. 批量导出已有笔记和复盘结果。

### 3.3 品牌与视觉语气

推荐采用“克制、温和、可信”的阅读工具风格：

- 不使用营销式大标题和夸张数据卡。
- 不依赖强渐变、毛玻璃和发光效果制造高级感。
- 使用稳定的排版、轻边界和少量品牌色强调交互。
- 页面首先应像个人阅读工作台，其次才像数据面板。

## 4. 目标

### 4.1 用户体验目标

1. 用户进入页面后，可在 3 秒内理解“这里是笔记中心”。
2. 无笔记时，用户无需阅读长文案即可知道下一步是“同步笔记”。
3. 有笔记时，用户能快速找到搜索入口和目标书籍。
4. 同步与导出的任务优先级清晰，不再呈现为两个同级主操作。
5. 建议复盘可以被发现，但不抢占书籍浏览主流程。
6. 宽屏、窄屏、浅色、深色和紧凑密度下均保持稳定层级。

### 4.2 工程目标

- 复用现有数据结构和事件处理函数。
- 不改变微信读书同步、统计和导出数据口径。
- 不引入新的 UI 组件库。
- 优先通过 JSX 层级调整、条件渲染和 CSS 完成。
- 保留中文输入法组合事件处理逻辑。

## 5. 非目标

本轮不做：

- 不新增本地“新建笔记”能力。
- 不新增书籍选择器或独立笔记编辑器。
- 不将笔记中心改造成三栏常驻布局。
- 不重做单本书笔记页。
- 不修改批量导出向导内部流程。
- 不改变统计口径、同步接口或缓存规则。
- 不实现复杂排序、自定义筛选器或虚拟列表。
- 不新增常驻局部侧边栏，避免与全局侧边栏竞争。

## 6. 当前实现基线

当前页面结构如下：

```text
笔记中心
├─ 页面头部
│  ├─ kicker：个人笔记
│  ├─ 标题：划线、想法和书签数量
│  ├─ 统计口径说明
│  ├─ 同步笔记
│  └─ 批量导出
├─ 五项统计
├─ 凭据状态 / 错误状态
├─ 建议复盘
├─ 搜索
├─ 加载 / 空状态 / 筛选无结果
├─ 书籍卡片网格
└─ 批量导出向导
```

已有合理实现应继续保留：

- 搜索仅在 `books.length > 0` 时出现，符合渐进式披露。
- 搜索支持中文输入法组合事件，不应退回逐字符提交。
- 无凭据、升级要求、普通错误、初始加载、无数据和搜索无结果均已有独立状态。
- 批量导出已有预检、进度、取消、结果和重试流程。
- 单本书笔记通过独立 `BookNotesPage` 承接。

## 7. 核心问题

### 7.1 页面标题与用户任务不匹配

当前标题“划线、想法和书签数量”描述的是数据内容，而不是页面用途。它与下方统计条重复，也无法覆盖搜索、复盘和导出等能力。

影响：

- 用户第一眼容易将页面理解为统计页。
- 标题和统计区重复表达，增加认知负担。
- 后续扩展能力时，标题越来越不准确。

### 7.2 顶部操作没有主次

`同步笔记` 和 `批量导出` 当前都使用 `sync-button`。

但两者的触发条件和任务频率不同：

- 同步是页面数据更新和空状态恢复的主动作。
- 导出只有在存在可导出内容时才有意义，属于次操作。

同级样式会迫使用户自己判断哪个按钮更重要。

### 7.3 空状态主动作被弱化

空状态已有正确动作“同步笔记”，但按钮使用 `secondary-action`。页面顶部同时还有一个同意图的同步按钮，形成两个权重接近的入口。

影响：

- 空状态中心缺少明确视觉锚点。
- 用户可能先看顶部、再看空状态，视线来回移动。
- 中部留白在缺少强动作时会被感知为“页面还没加载完”。

### 7.4 有数据状态信息密度缺少节奏

统计、建议复盘、搜索和书籍卡片连续出现。建议复盘使用完整面板和三张卡片，有时会比核心书籍列表更醒目。

影响：

- 高频任务“找一本书”被建议模块下压。
- 页面呈现多个相似卡片区域，缺少主内容与辅助内容的区别。
- 首屏能展示的书籍数量下降。

### 7.5 宽屏伸展与空白失衡

书籍网格使用：

```css
grid-template-columns: repeat(auto-fill, minmax(250px, 1fr));
```

当内容容器很宽时，卡片可能持续拉伸；当卡片数量少时，右侧会出现不稳定空白。截图中的视觉重心偏左，本质上也是内容宽度与实际信息量不匹配。

## 8. 设计原则

### 8.1 一屏一个主任务

- 空数据：主任务是同步。
- 有数据：主任务是查找并打开一本书。
- 批量导出始终是次任务，不与同步竞争主按钮。

### 8.2 状态决定界面复杂度

- 无凭据：只突出凭据设置。
- 无笔记：只突出同步。
- 有笔记：再展示搜索、复盘建议和导出。
- 搜索无结果：只突出清空搜索。

### 8.3 统计是上下文，不是主内容

统计帮助用户理解规模，但不应成为五张高权重卡片。继续保留轻量统计条，不增加图表或趋势装饰。

### 8.4 主内容优先于推荐内容

书籍列表是稳定主内容；建议复盘是辅助发现模块。辅助模块可以靠近搜索，但不能在视觉重量和面积上压过书籍列表。

### 8.5 不暴露不存在的能力

当前产品数据来源是微信读书同步。空状态不加入“新建笔记”“创建文件夹”等按钮，避免制造无法完成的用户预期。

### 8.6 保持阅读工具的克制感

减少同质卡片、重复说明和无意义装饰。通过排版、间距、边界和交互状态形成层级，而不是为每个区域增加阴影和渐变。

## 9. 推荐信息架构

### 9.1 无凭据

```text
个人笔记
笔记中心
同步微信读书的划线、想法和书签。

[凭据设置卡]
  先保存 API Key
  保存后即可同步笔记。
  [前往设置]
```

规则：

- 不显示统计条。
- 不显示同步和批量导出按钮。
- 不显示搜索、建议复盘和书籍网格。
- 页面只有一个主动作：前往设置。

### 9.2 有凭据但无笔记

```text
个人笔记
笔记中心                                      [同步笔记]
同步微信读书的划线、想法和书签。

[轻量空状态插图]
还没有同步笔记
同步后可按书查看划线、想法和书签。
[同步笔记]
```

推荐行为：

- 页面头部仍可保留同步按钮，便于形成稳定布局。
- 空状态中的同步按钮是当前视觉主按钮。
- 两个入口调用同一 `loadOverview()`，但空状态入口权重更高。
- 不显示批量导出。
- 统计条可隐藏；如果为了避免同步前后布局跳动而保留，也必须降为低对比度，不展示五个醒目的 `0`。

P0 推荐：无笔记时隐藏统计条和批量导出，以减少无效信息。

### 9.3 有笔记

```text
个人笔记
笔记中心                         [批量导出] [同步笔记]
同步微信读书的划线、想法和书签。

有笔记书籍 24 · 总笔记 837 · 划线 690 · 想法 126 · 书签 21

[按书名或作者筛选笔记                         ]

建议复盘  3 本
优先整理这些有想法的书
[书 A] [书 B] [书 C]

全部笔记书籍
[书籍卡片] [书籍卡片] [书籍卡片]
```

层级说明：

1. 页面头部：确认页面身份和全局操作。
2. 统计条：提供规模上下文。
3. 搜索：承接主要浏览任务。
4. 建议复盘：辅助发现，可在视觉上收紧。
5. 书籍网格：页面主内容。

## 10. 详细设计

### 10.1 页面标题

建议替换：

```text
个人笔记
笔记中心
同步微信读书的划线、想法和书签。
```

对应 JSX：

```tsx
<p className="section-kicker">个人笔记</p>
<h3>笔记中心</h3>
<p>同步微信读书的划线、想法和书签。</p>
```

不再在标题区展示：

```text
书签只纳入统计；正文内容只展示和导出划线、想法/点评。
```

这段属于数据边界说明，不是页面价值主张。推荐处理方式：

- 移至统计条下方的弱辅助说明；或
- 移至批量导出向导的边界说明中；或
- 仅在用户需要时通过信息提示展示。

P0 推荐：从头部移除，不新增提示控件。批量导出向导已经包含更完整的导出边界说明。

### 10.2 顶部操作

#### 有笔记时

- `同步笔记`：主按钮。
- `批量导出`：次按钮。
- 按钮顺序建议为“批量导出、同步笔记”，让主按钮位于操作组最右侧，符合桌面端提交动作习惯。

示例：

```tsx
<button className="secondary-action">批量导出</button>
<button className="primary-action">同步笔记</button>
```

如果项目现有主按钮仍统一使用 `sync-button`，建议新增明确语义修饰类，而不是继续让两个动作共用完全相同样式：

```tsx
<button className="sync-button sync-button--secondary">批量导出</button>
<button className="sync-button sync-button--primary">同步笔记</button>
```

#### 无笔记时

- 隐藏 `批量导出`。
- 保留头部同步按钮，空状态中再提供更强的同步入口。
- 同步中两个入口都禁用，并统一展示“同步中”。

#### 无凭据时

- 隐藏整个操作组。

### 10.3 统计条

继续使用单行轻量统计，不改为五张独立大卡片。

建议内容：

```text
有笔记书籍 24  ·  总笔记 837  ·  划线 690  ·  想法 126  ·  书签 21
```

视觉规则：

- 统计项高度建议 36–40 px。
- 标签使用辅助文字色，数字使用正文色或品牌深色。
- 不使用大字号数字、强阴影或彩色图标。
- 宽度不足时允许自然换行，保持 8–10 px 行列间距。
- `想法/点评` 在空间受限时可显示为 `想法`，但统计口径不变。
- 无笔记状态不显示统计条。

### 10.4 搜索

保留当前仅在有书时显示的规则。

建议：

- 搜索位于统计条之后、建议复盘之前。
- 桌面端最大宽度建议 520–640 px，不必横向铺满整个内容区。
- 输入框高度建议 40–44 px。
- 保留占位文案“按书名或作者筛选笔记”。
- 保留 `onCompositionStart` / `onCompositionEnd` 处理。
- 有输入时可在后续版本增加清除图标；P0 不是必需。

### 10.5 建议复盘

建议复盘是辅助模块，应从“大面板”调整为“轻量内容段”。

#### 推荐结构

```text
建议复盘                                      3 本
优先整理这些有想法的书
[书 A] [书 B] [书 C]
```

视觉规则：

- 保留最多 3 本的现有数据规则。
- 外层可保留浅色背景，但降低阴影和边框对比度。
- 标题字号低于页面标题，高于卡片标题。
- 卡片高度与书籍主网格区分，可保持更紧凑。
- 不使用过强的 `Sparkles` 装饰；图标仅作为轻提示。
- 如果首屏高度不足，优先收紧建议卡片，而不是压缩搜索和书籍卡片可读性。

#### 可选后续方案

如果实际使用数据显示建议复盘点击率较低，可将其移动到书籍网格之后。P0 先保留在搜索与书籍网格之间，以较小改动验证层级。

### 10.6 书籍网格

书籍网格是有数据状态的主内容。

建议增加区段标题：

```text
全部笔记书籍                              共 24 本
```

区段标题的价值：

- 将主内容与建议模块明确分开。
- 搜索后可显示“筛选结果”或结果数量。
- 为未来排序能力预留稳定位置，但本轮不新增排序。

#### 网格规则

推荐桌面端：

```css
.notebook-grid {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(268px, 320px));
  gap: 14px;
  justify-content: start;
}
```

该方案避免卡片在超宽屏上无限拉伸，同时保持左对齐的稳定节奏。

如果希望网格始终填满内容区，可使用断点控制列数：

```css
.notebook-grid {
  grid-template-columns: repeat(3, minmax(0, 1fr));
}

@media (max-width: 1180px) {
  .notebook-grid {
    grid-template-columns: repeat(2, minmax(0, 1fr));
  }
}

@media (max-width: 760px) {
  .notebook-grid {
    grid-template-columns: 1fr;
  }
}
```

P0 推荐第一种 `auto-fill + 最大卡片宽度 + justify-content: start`，改动小且可直接修复宽屏拉伸。

#### 卡片规则

- 书名最多两行，继续保留截断。
- 作者最多一行，超出省略。
- 封面宽高比稳定，不因缺图改变网格高度。
- “划线、想法”属于内容构成，保持辅助层级。
- “总笔记”继续作为卡片底部主要数值。
- hover 仅使用轻微背景、边框和 1 px 位移，不增加夸张阴影。
- 键盘焦点必须有清晰可见的 `:focus-visible` 样式。

### 10.7 空状态

#### 推荐文案

```text
还没有同步笔记
同步后可按书查看划线、想法和书签。
[同步笔记]
```

相较当前文案，删除“并支持进入单本书查看内容”等说明书式表达，保留用户最需要的信息。

#### 布局规则

- 作为页面主体中的独立空状态区，不需要铺满剩余全部高度。
- 建议最大宽度 680–760 px。
- 上下内边距 32–40 px，避免形成过大的空白容器。
- 图片仅用于建立阅读语境，不应超过正文视觉重量。
- 主按钮使用页面主操作样式。
- 不增加“新建笔记”“选择书籍”等当前产品不支持的动作。

### 10.8 搜索无结果

保留当前结构：

```text
没有匹配的笔记书籍
换一个关键词，或清空搜索后继续浏览。
[清空搜索]
```

优化规则：

- 不显示全局无笔记插图，避免与初次空状态混淆。
- 保留搜索框及用户输入。
- `清空搜索` 是当前状态的唯一恢复动作。
- 建议复盘是否参与搜索过滤应保持现状，不在 P0 改变其数据逻辑。

### 10.9 加载状态

当前使用 6 个卡片骨架，方向正确。

建议：

- 初次加载无书时显示标题区、同步按钮禁用态和 6 个骨架。
- 已有缓存书籍时执行同步，不要用骨架覆盖现有内容；保留当前书籍并只显示按钮 loading。
- 骨架尺寸与最终卡片一致，避免布局跳动。
- 加载区域使用 `aria-label="正在读取笔记"`，同步结果可通过既有 toast 或状态区域反馈。

### 10.10 错误与升级状态

#### 普通错误

- 错误消息显示在标题和统计区之后、主内容之前。
- 不应因摘要加载失败而永久阻断已有书籍浏览；如果错误来自 `listBookNotesSummaries()`，建议后续拆分为复盘建议局部错误。
- P0 可维持单一错误状态，但应确认已有书籍仍可见。

#### 升级要求

- 继续使用 `SkillUpgradeNotice`。
- 重试动作仍调用 `loadOverview()`。
- 不在同一状态再叠加普通错误提示。

#### 批量导出错误

- 继续由向导内部的 `ExportFailurePanel` 承接。
- 不将导出错误提升为页面级错误，避免阻断笔记浏览。

## 12. 视觉规范

### 12.1 内容宽度

- 页面内容区建议设置稳定最大宽度，例如 `1440px`。
- 页面左右内边距使用现有全局布局规则，不在 `NotesPage` 重复写固定窗口边距。
- 空状态、搜索等窄内容使用局部最大宽度，不强制铺满。

### 12.2 间距节奏

建议以 4 px 为基础单位：

- 标题 kicker 到标题：4–6 px。
- 标题到说明：6–8 px。
- 页面头部到统计条：12–16 px。
- 统计条到搜索：16–20 px。
- 搜索到建议复盘：16–20 px。
- 建议复盘到书籍主区域：20–24 px。
- 网格间距：14–16 px。

`compact` 密度下整体间距缩小约 20%，但按钮可点击高度和正文行高不应过度压缩。

### 12.3 排版

- 页面标题：约 `1.625rem–1.75rem`，保持现有层级。
- 区段标题：约 `1rem–1.125rem`。
- 正文说明：约 `0.875rem–0.9375rem`，行高不低于 1.55。
- 卡片书名：约 `1rem–1.0625rem`。
- 辅助信息：不低于 `0.75rem`，并确保对比度可读。
- 不通过全大写、过宽字距或过多粗体制造层级。

### 12.4 色彩与边界

- 使用现有 CSS 变量：`--ink`、`--muted`、`--line`、`--green`、`--surface-*`。
- 浅色主题避免纯白大面积卡片堆叠，可继续使用带纸张感的暖色表面。
- 深色主题必须使用对应表面变量，禁止硬编码浅色 hover 背景。
- 边框优先于阴影表达层级；阴影只用于少量可交互卡片。
- 主按钮颜色和对比度需同时满足浅色、深色主题。

### 12.5 动效

- 同步图标旋转继续复用 `.spin`。
- 卡片 hover 位移不超过 1–2 px。
- 颜色和边框过渡建议 120–180 ms，使用平滑 ease-out。
- 不对网格列数、宽高等布局属性添加动画。
- 遵守 `prefers-reduced-motion`，减少非必要位移动效。

## 13. 响应式规则

### 13.1 宽屏桌面（≥ 1280 px）

- 标题与操作同一行。
- 搜索最大宽度 640 px。
- 书籍卡片保持稳定最大宽度，不无限拉伸。
- 建议复盘最多三列。

### 13.2 中等窗口（760–1279 px）

- 标题与操作仍优先同一行；空间不足时操作组换行。
- 书籍网格两列或自动适配。
- 统计条允许换行。
- 建议复盘两列或单列。

### 13.3 窄窗口（< 760 px）

- 标题与操作纵向排列。
- 操作按钮可等宽或按内容宽度排列，但主按钮仍保持清晰。
- 搜索铺满可用宽度。
- 书籍网格单列。
- 空状态插图缩小，文案和按钮保持居中或左对齐一致。
- 不隐藏同步、搜索、导出等关键功能，只调整布局。

### 13.4 紧凑密度

继续支持：

```css
.app-frame[data-density="compact"] .notes-page
```

补充规则：

- 页面区段间距缩小。
- 卡片内边距和网格间距适度缩小。
- 搜索框和主要按钮高度不低于可用点击标准。
- 不通过缩小正文到不可读字号实现紧凑。

## 14. 可访问性要求

- 页面根节点继续使用 `aria-label="笔记中心"`。
- 操作组继续使用 `aria-label="笔记操作"`。
- 纯装饰图片使用空 `alt`，空状态标题承担语义。
- 图标按钮必须有明确 `aria-label`；图标与文字组合按钮中的图标使用 `aria-hidden="true"`。
- 所有按钮、书籍卡片和输入框需要可见的 `:focus-visible` 状态。
- 禁用按钮不仅依赖颜色，需保留光标和透明度等状态差异。
- 错误区域应可被读屏读取；异步状态按需使用 `aria-live="polite"`。
- 正文和辅助文字对比度至少达到 WCAG AA 的常规文本要求。
- 在 200% 缩放时不得出现操作遮挡、文本截断导致关键信息丢失。

## 19. 风险与缓解

### 风险 1：隐藏无数据统计造成同步前后布局跳动

缓解：

- 允许状态变化带来自然内容展开，不为避免跳动而长期显示无意义零值。
- 保持标题区高度稳定即可。

### 风险 2：建议复盘前后顺序影响已有用户习惯

缓解：

- P0 只将搜索前置，不将建议复盘移到页面末尾。
- 通过使用数据和点击率决定后续位置。

### 风险 3：限制卡片最大宽度后右侧仍有空白

缓解：

- 这是有节奏的留白，不等同于内容区失衡。
- 使用稳定卡片宽度和左对齐，可提升扫读效率。
- 如果产品更偏好铺满布局，可切换为断点控制列数方案。

### 风险 4：共用全局按钮类导致其他页面被影响

缓解：

- 优先使用 `NotesPage` 局部修饰类。
- 不直接重定义全局 `.sync-button` 或 `.secondary-action` 的基础语义。

### 风险 5：摘要加载错误阻断整个页面

缓解：

- 后续可拆分 overview error 与 summary error。
- 复盘建议失败时，只隐藏或局部提示该模块，不阻断书籍浏览。
- 该项可作为 P1，不阻塞 P0 视觉改造。

## 20. 与单本书笔记页的边界

笔记中心负责：

- 同步状态与总体统计。
- 搜索和选择书籍。
- 建议复盘入口。
- 批量导出入口。

单本书笔记页负责：

- 书籍信息。
- 章节目录。
- 划线、想法和点评正文。
- 单本书筛选、展开和导出。
- AI 复盘内容。

本次不把截图中的三栏笔记编辑器结构直接引入当前产品。现有应用已经有全局侧边栏，单本书页面也已有“顶部轻工具栏 + 可折叠章节目录 + 正文区域”的独立规划。增加常驻局部侧栏会造成导航层级竞争，并显著扩大改造范围。

## 22. 决策摘要

P0 最值得优先落地的三项：

1. **强化同步主动作**：标题任务化，空状态同步按钮升级，导出降为有数据时的次操作。
2. **收紧空状态和统计噪声**：无笔记时隐藏零值统计，不引入不存在的新建能力。
3. **稳定有数据布局**：搜索前置，建议复盘降权，书籍网格限制卡片伸展并增加主区段标题。

该方案不改变业务能力，不引入新的导航结构，能以较低工程风险解决当前页面的视觉重心、操作层级和宽屏布局问题。
