# Notion 成果页展示模板设计

wxreadmaster · 页面正文模板 · 2026\-07\-26

本文设计五类阅读成果在 Notion **页面内部**的展示模板（成果页正文），与《notion\-reading\-workspace\-ui\-design》（首页/工作台）互补。目标是把现状的"Markdown 直译"升级为按 Notion 块语言原生排版的阅读页面，同时顺带解决《Notion 一键导出问题分析》中的 P0 正文保真度问题。

## 1\. 设计结论

成果页的阅读体验取决于一件事：**读者打开页面时在做什么**。回看笔记的人在"扫读—定位—细读"，不是从头读到尾。因此模板的核心不是把内容排全，而是建立三层视觉声部——

> 原文（他者文本）用 quote，我的想法（自我文本）用 callout，系统元信息（时间、位置、ID）降级为灰色小字。

再配合"结论先行 \+ 目录导航 \+ 次要信息渐进披露"，一页笔记就能同时支持 10 秒扫读和 10 分钟细读。

## 2\. 阅读习惯五原则

**结论先行（倒金字塔）**。打开页面 3 秒内要能回答"这页有什么、值不值得往下读"。每页第一屏固定为：一个摘要 callout（数量、进度、导出时间一句话）＋目录。统计、元数据流水账不配出现在第一屏——数据库模式下这些已经在属性区了。

**他者文本与自我文本分离**。读书笔记页面最重要的排版决策：划线是书的话，想法是我的话，两者混排时必须一眼可分。方案是固定映射——划线→quote 块；想法→带 💭 图标的 callout；AI 生成内容→带 🤖/🧠 图标的 callout。读者扫一列左边框（quote）就是重温原书，扫一列色块（callout）就是重温自己的思考。

**渐进披露**。位置、划线时间、Prompt 版本这类信息有存档价值、无阅读价值。它们不该以独立段落打断纵向阅读流，而是收进两个层级：灰色行内小字（rich\_text `color: gray`，跟在正文块内的第二行）或 toggle（整节收纳）。Obsidian 的 `^块ID` 之类目标专用锚点则完全不进 Notion。

**可扫读的骨架**。页面提供 `table_of_contents` 块做章节跳转；章节标题层级稳定（章＝heading\_2，划线/想法小节不再单设标题，靠块类型自然区分）；划线特别多的章节用可折叠标题（`is_toggleable`），先看目录再展开感兴趣的章。所有布局在手机端单列下仍然成立（Notion 移动端会把分栏竖排堆叠）。

**可行动**。Notion 页面的价值是"还能继续用"：行动项用 to\_do（可持续勾选）、复盘问题用 toggle（先自己想再展开）、导入状态靠属性流转。页面不是存档，是工作台的延伸。

配色沿用工作台的资产语义色，跨页面保持一致：书籍笔记＝绿、书籍复盘＝蓝、统计复盘＝黄、阅读路线＝橙、选书决策＝紫。每页的摘要 callout 用本资产色，正文内的想法 callout 统一用 `gray_background`（避免整页彩色噪音，色彩只用于"页面身份"和少量强调）。

## 3\. 通用页面骨架

```text
[Page cover：书封 / 主题图]   [icon：📒 🧠 📈 🗺️ 🧩 按资产类型]

（数据库模式）属性区由 Notion 原生渲染，正文不重复元数据
（页面模式）  顶部分栏：左窄列封面图 · 右列灰字元数据

① 摘要 callout（资产色）——一句话讲清这页有什么
② table_of_contents ——超过 3 个章节/小节时才放
③ 主体内容 ——按资产类型见 §4–§8
④ 页尾：边界说明 quote（导出口径）＋外部链接
```

两条通用规则：

- **模板按 parent 类型自适应**。数据库模式下删掉"元数据/统计"小节（属性区已承载，正文重复是当前最明显的冗余）；页面模式下才在顶部保留一个紧凑的元数据区。
- **封面只出现一次**。pageCover 模式写 page cover、正文不再插封面图；contentImageOnly 模式才在正文顶部放图（解决现状的封面双份）。

## 4\. 书籍笔记页（旗舰模板）

```text
🧭 callout·绿：12 章 · 划线 86 · 想法 14 · 进度 72%
              基于本地缓存导出于 2026-07-21 14:03
[table_of_contents]

⭐ 本书精华（可选，3–5 条带想法的划线，quote）
---
## 第 3 章 深度工作的四种哲学        ← 划线多时 is_toggleable
> 将最重要的事放在最不受打扰的时间。
> ‹位置 210–260 · 2026-06-30›        ← 同块第二行，灰字
💭 想法：对应我早上 6–8 点的写作块。
   ‹关联原文"将最重要的事…" · 2026-07-01›   ← 灰字
> 下一条划线……
---
> 边界说明：书签仅计数，正文未包含（微信读书接口限制）。
🔗 在微信读书中打开本书（URL 有效时才放）
```

关键决策：

- **划线与想法按章节内位置混排**，想法紧跟它评注的那条划线，而不是现状的"划线一节＋想法一节"。回看时"原文→我的反应"是一个完整的阅读单元，拆开就要来回滚动。`HighlightRecord`/`ThoughtRecord` 都有 range，可按 range 起点排序合并；无 range 的想法归入章节尾部。
- **每条划线收敛为 1 个 quote 块**：正文 run＋换行＋灰色 run（位置·时间）。现状是每条 2–3 块（quote＋`_划线时间_ ^id` 段落），新模板直接把块数减半以上——同时缓解 100 块/批的限流与半成品页风险。
- **每条想法收敛为 1 个 callout 块**（💭 · `gray_background`）：想法正文＋灰色 run（关联原文摘句·评分·时间）。读完点评（`is_finish`）图标换 🏁 以示区分。
- **精华区可选**：优先选带想法的划线（自我加工过的内容回看价值最高），上限 5 条，超出即省略。没有合适条目时整节不出现——空节比无节更伤阅读。

## 5\. 书籍复盘页（AI 复盘）

```text
🧠 callout·蓝：一句话概览（overview 首句或全文）
[table_of_contents]
## 关键观点
1. 观点一……                     ← numbered list，每条 1 块
## 行动项
[ ] 把手机移出书房                ← to_do，导入后可直接勾
[ ] 每周日 30 分钟周复盘
## 复盘问题
▸ 这本书最想让我改变的一个行为是什么？   ← toggle：问题即标题
    （展开后是 AI 提示或留白，供自己作答）
## 代表性摘录
> 摘录原文……‹第 3 章›
▸ 行动/问题反馈记录（toggle 收纳历史反馈）
> 依据说明：基于 86 条划线与 14 条想法生成 · book-review-v3
```

行动项用 to\_do 是这页的灵魂——复盘的产出物变成可勾选清单，页面从"读后感存档"变成"待办来源"，也和首页"行动优先"视图（行动数 \> 0）形成闭环。复盘问题用 toggle 是刻意的阅读节奏设计：先看到问题、想一下、再展开。AI 溯源信息（Prompt 版本、输入哈希）只进属性，正文最多留一行灰字依据说明。

## 6\. 统计复盘页

```text
📈 callout·黄：本期一句话结论（AI 摘要首句）
┌ 分栏 column_list ×3 ┐
│ 🕘 阅读 21.5h │ 📚 读完 3 本 │ ✍️ 划线 210 条 │   ← 每格一个 callout 数字卡
└──────────────┘
## 趋势解读
（AI 生成段落，经行内解析后写入）
## 周期明细
[table 块：周/月 × 时长/册数/划线]
▸ 口径说明（toggle：统计窗口、时区、数据来源）
```

数字卡用分栏 callout 模拟 stat tile——Notion 没有原生数字卡，三列 callout 是社区通用做法，手机端自动竖排。明细用原生 table 块而不是竖线文本。

## 7\. 阅读路线页 / 选书决策页

阅读路线（橙）：当前书 callout 先行（书名＋阶段＋一句推进理由）→ 推进顺序 numbered list（每本一行：书名·预计投入·理由摘句）→ 检查点 to\_do → 候选书 toggle 收纳。选书决策（紫）：**结论先行**——第一屏就是"选了《X》＋核心依据一句话"的 callout，然后才是对比 table（候选 × 维度）、取舍理由 bulleted、触发条件 to\_do。两页共同点：把"决定"放在最前，把"论证"放在后面，符合决策类内容的回看习惯（多数时候只想确认当时定了什么）。

## 8\. 块使用规范（速查）

| 内容 | 块类型 | 说明 |
| --- | --- | --- |
| 页面摘要 | callout·资产色 | 每页恰好 1 个，第一屏 |
| 书中原文/划线/摘录 | quote | 元信息灰字并入同块第二行 |
| 我的想法/点评 | callout 💭 gray | 关联原文摘句灰字并入 |
| AI 段落内容 | paragraph（经行内解析） | 粗体→bold，https 链接→link，`weread://`→纯文本 |
| 行动项/检查点 | to\_do | 永不默认勾选 |
| 复盘问题/口径说明/历史反馈 | toggle | 渐进披露层 |
| 数字卡 | column\_list \+ callout | ≤4 列；手机端自动竖排 |
| 明细数据 | table 块 | 替代竖线文本表 |
| 章节 | heading\_2（长章 is\_toggleable） | 小节不再另设 heading\_3 |
| 目录 | table\_of\_contents | 章节 \>3 时 |
| 边界/免责 | quote | 页尾，弱视觉 |
| 分隔 | divider | 每页 ≤3 处：精华区前后、页尾前 |

灰字统一用 rich\_text `annotations.color = "gray"`，元信息前后可用 `‹›` 或 `·` 分隔；不用斜体下划线语法（那是 Markdown 的事）。

## 9\. API 可行性与块数预算

所用块类型（quote、callout、toggle、to\_do、numbered/bulleted、heading `is_toggleable`、table\_of\_contents、column\_list/column、table/table\_row、divider、bookmark、image）均为 Notion API `2022-06-28` 稳定能力，无需依赖 linked view、按钮或数据库模板。三点工程注意：

- **嵌套随父块同批提交**。column\_list→column→内容、toggle→children 必须在同一请求内成树提交（现有 100 块/批的切分按顶层数组计，嵌套不会被拆开，天然安全）；嵌套块计入单请求总块数上限，分栏区不要贪多。
- **块数预算显著改善**。现状每条划线 2–3 块、每条想法 2–5 块；新模板各收敛为 1 块。86 条划线＋14 条想法的书从约 260 块降到约 130 块，追加批次减半，限流与"半成品页"风险同步下降。
- **实现路径**：为书籍笔记新增 `build_book_notes_blocks(&BookNotesRecord)` 直接产出块树（不再走 Markdown 中间态）；AI 类资产保留 Markdown 输入，但升级 `markdown_to_blocks` 为"块级＋最小行内解析"（bold、行内 code、https 链接、剥 front matter 与 `^块ID`、表格→table 块）。两者共用行内解析器。此路径落地即消掉《问题分析》中 P0 的 1/2/3 号问题。

## 10\. 非目标

不做双向同步与已有页面更新；不自动创建 linked database 视图；不引入数据库模板页；不给正文加大段使用教程（教程属于工作台首页）；不追求还原微信读书的划线颜色（数据不稳定，首版忽略）。

## 11\. 验收标准

- 打开任一成果页，第一屏可见摘要 callout；数据库模式正文无重复元数据，无 YAML/`^块ID`/裸链接残留。
- 划线与想法在章节内按位置相邻呈现，quote 与 callout 视觉可区分；元信息为灰字且不独占块。
- 书籍复盘页行动项可勾选，复盘问题默认折叠。
- 章节 \>3 的页面有可用目录；\>100 块的书导出后无"半成品页"投诉路径变化（配合部分成功语义）。
- 五类资产页第一屏 callout 颜色与数据库 `资产类型` select 色一致。
- 手机端浏览分栏区无横向滚动。
- 同一本书旧版导出页与新版并存时互不影响（只创建新页原则不变）。
