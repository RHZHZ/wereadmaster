# Notion 阅读成果工作台设计

## 1. 设计结论

截图里的方向可以作为 wxreadmaster 的 Notion 模板目标形态，但不应只做成“漂亮首页”。结合当前应用可导出的成果，Notion 端应该定位为：

> 一个以书籍为入口、以成果为主线、以复盘行动为落点的阅读知识库。

首版建议采用“一个首页 + 一个核心成果数据库”的结构：

- 首页负责导航、说明、成果分区和视觉呈现。
- 核心数据库负责承接所有导出结果。
- 每次导出创建一条 Notion 页面，正文保存完整 Markdown 转换内容。
- 页面属性保存可筛选、可排序、可追踪的元数据。

不建议首版拆成多张强关系数据库。多数据库关系看起来更像完整 Notion 模板，但会显著增加 API 初始化、字段迁移、用户理解和失败恢复成本。

## 2. 当前应用可导出的成果

当前应用已形成五类可导出成果，均可进入 Markdown、Obsidian、Notion 多目标导出链路。

| 成果 | ExportSourceKind | 主要内容 | Notion 中的角色 |
| --- | --- | --- | --- |
| 书籍笔记 | `bookNotes` | 元数据、封面、划线、想法/点评、章节分组、统计 | 原始阅读证据 |
| 书籍 AI 复盘 | `bookReview` | 概览、主题标签、关键观点、关注点、行动项、代表性摘录、复盘问题、反馈状态 | 单本书沉淀成果 |
| 阅读统计复盘 | `readingStatsReview` | 周/月/年/总览复盘、节奏洞察、偏好洞察、下一步行动、阅读人格补丁 | 阶段性阅读回顾 |
| 阅读路线 | `readingRoute` | 当前书、候选书、阅读顺序、依赖关系、检查点、下一步行动、阅读阶段 | 多书主题路线 |
| 选书决策 | `bookDecision` | 候选书排序、为什么现在读、取舍、预计投入、前置动作、复盘触发点 | 下一本书选择记录 |

这些成果的共同点：

- 都有标题、来源类型、导出时间。
- 多数有 `bookId` 或 `scopeId`。
- AI 成果都有 `promptVersion`、`inputHash`、`basisNotice`。
- 书籍相关成果可能有作者和封面。
- 正文结构差异较大，不适合强行拆成统一 Notion 子表。

因此，Notion 设计的核心不是把所有内容拆字段，而是把“可筛选元数据”和“完整正文页面”分层。

## 3. Notion 信息架构

### 3.1 首页

页面名称建议：`微信读书知识库`

首页布局类似用户截图，但做成更贴合应用的阅读成果工作台：

```text
微信读书知识库

导航
  书籍笔记
  书籍复盘
  阅读路线
  统计复盘
  选书决策

今日入口
  最近导入
  待读整理
  有行动项

核心数据库
  阅读成果库
```

视觉目标：

- 顶部可以使用品牌封面图或 Notion 默认封面。
- 页面 icon 使用书本或种子类 emoji，例如 `📚`。
- 首屏只放导航和最近成果，不堆说明文字。
- 数据库标题用清晰分组，不做花哨但低信息密度的卡片。

### 3.2 核心数据库

数据库名称：`阅读成果库`

每条记录代表“一次可导出的成果”，而不是“一本书”。例如同一本书可以有：

- 一条 `书籍笔记`
- 多条不同时间的 `书籍复盘`
- 一条或多条 `阅读路线`
- 若干次 `选书决策`

这样可以天然保留版本历史，不需要做覆盖式同步。

### 3.3 视图

首版可在文档和用户指引中定义这些视图。API 初始化阶段先创建数据库和字段；复杂视图可以作为后续增强。

| 视图 | 过滤/排序 | 用户价值 |
| --- | --- | --- |
| 全部成果 | `导出时间` 倒序 | 最近导入工作台 |
| 书籍笔记 | `资产类型 = 书籍笔记` | 查原始划线和想法 |
| 书籍复盘 | `资产类型 = 书籍复盘` | 查 AI 总结、行动项和复盘问题 |
| 阅读路线 | `资产类型 = 阅读路线` | 查多书路线和检查点 |
| 统计复盘 | `资产类型 = 阅读统计复盘` | 查周期回顾 |
| 选书决策 | `资产类型 = 选书决策` | 回看为什么选这本 |
| 待读整理 | `导入状态 = 待整理` | Notion 内二次加工入口 |

## 4. 字段设计

### 4.1 P0 字段

这些字段应由一键模板创建，并由当前导入流程优先写入。

| 字段 | 类型 | 写入来源 | 说明 |
| --- | --- | --- | --- |
| `名称` | Title | `ExportDocument.title` | Notion 页面标题 |
| `作者` | Rich text | `ExportDocument.author` | 无作者则留空 |
| `Book ID` | Rich text | `bookId` 或 `sourceId` | 用于跨工具定位 |
| `资产类型` | Select | `ExportSourceKind` | 五类成果枚举 |
| `来源` | Select | 固定 `wxreadmaster` | 后续可区分 Obsidian/手动整理 |
| `导出时间` | Date | `exportedAt` | 用于排序 |
| `导入状态` | Select | 默认 `已导入` | 用户可改为待整理/已归档 |
| `Prompt 版本` | Rich text | `frontMatter.promptVersion` | AI 成果版本 |
| `输入哈希` | Rich text | `frontMatter.inputHash` | AI 成果去重与追踪 |

### 4.2 P1 字段

这些字段建议保留，但不要求首轮全部自动写入。

| 字段 | 类型 | 适用成果 | 说明 |
| --- | --- | --- | --- |
| `阅读阶段` | Select | 书籍复盘、阅读路线 | 起步、建立主线、深入、收束、完成 |
| `进度` | Number | 书籍笔记、书籍复盘、阅读路线 | 阅读进度百分比 |
| `标签` | Multi-select | 书籍复盘 | 来自 AI 主题标签 |
| `周期` | Select | 阅读统计复盘 | 周、月、年、总览 |
| `行动数` | Number | 书籍复盘、统计复盘、路线、决策 | 下一步行动数量 |
| `候选书数` | Number | 阅读路线、选书决策 | 路线/决策涉及书籍规模 |
| `微信读书` | URL | 有真实 `bookId` 的书籍成果 | 指向微信读书网页详情；统计复盘和本地预览 ID 不生成伪链接 |
| `Obsidian 路径` | Rich text | 双目标导出 | 记录本地 Vault 文件路径 |

### 4.3 不建议字段化的内容

这些内容保留在页面正文，不拆成数据库字段：

- 每条划线全文。
- 每条想法/点评全文。
- 代表性摘录全文。
- 阅读路线依赖关系。
- 选书决策的详细理由。
- 阅读统计中的完整洞察段落。

原因：这些内容结构复杂、长度不稳定，拆字段后筛选价值有限，还会让数据库变重。

## 5. 各成果页面结构

### 5.1 书籍笔记页

页面属性：

- `名称`：书名
- `资产类型`：书籍笔记
- `作者`
- `Book ID`
- `导出时间`

正文结构：

```text
元数据
统计
章节 A
  划线
  想法/点评
章节 B
  划线
  想法/点评
```

Notion 中用途：作为可追溯证据库，复盘和路线都可以回到这里核对原文笔记。

### 5.2 书籍 AI 复盘页

页面属性：

- `资产类型`：书籍复盘
- `Prompt 版本`
- `输入哈希`
- `标签`
- `阅读阶段`
- `行动数`

正文结构：

```text
导出边界
概览
主题标签
关键观点
我的关注点
行动项
行动反馈记录
代表性摘录
复盘问题
复盘问题反馈记录
来源统计
```

Notion 中用途：这是用户真正复用频率最高的成果页。建议首页把“最近书籍复盘”和“有行动项”作为突出入口。

### 5.3 阅读统计复盘页

页面属性：

- `资产类型`：阅读统计复盘
- `周期`
- `导出时间`
- `Prompt 版本`
- `输入哈希`

正文结构：

```text
周期概览
阅读节奏洞察
偏好洞察
重点关注
下一步行动
阅读人格
来源统计
```

Notion 中用途：用于周/月/年复盘，不强绑定某一本书。

### 5.4 阅读路线页

页面属性：

- `资产类型`：阅读路线
- `Book ID` 或 `scopeId`
- `阅读阶段`
- `候选书数`
- `Prompt 版本`
- `输入哈希`

正文结构：

```text
路线概览
阅读顺序
书籍依赖关系
复盘检查点
下一步行动
来源统计
```

Notion 中用途：承接“我接下来怎么读”的计划，不建议拆成独立任务库，首版先作为页面内容管理。

### 5.5 选书决策页

页面属性：

- `资产类型`：选书决策
- `Book ID` 或 `scopeId`
- `候选书数`
- `导出时间`
- `Prompt 版本`
- `输入哈希`

正文结构：

```text
决策概览
优先候选
  为什么现在读
  取舍
  预计投入
  前置动作
  复盘触发点
暂缓候选
下一步行动
来源统计
```

Notion 中用途：记录选择依据，避免“当时为什么要读这本”丢失。

## 6. 首页视觉设计

参考截图可以抽象为三块：

- 左侧是模板说明和操作。
- 右侧是 Notion 页面预览。
- 页面首屏有封面、标题、导航、数据库分区。

应用内设置页可以继续使用这个思路，但要更工具化：

```text
Notion 阅读库
  连接状态：Token / 父页面 / 目标数据库
  模板预览：封面 + 导航 + 阅读成果库字段
  操作：创建阅读库数据库 / 保存高级目标 / 测试连接
```

Notion 实际页面建议：

```text
[封面图]
📚 微信读书知识库

导航
书籍笔记 | 书籍复盘 | 阅读路线 | 统计复盘 | 选书决策

最近导入
阅读成果库

整理队列
过滤：导入状态 = 待整理
```

注意：Notion API 能稳定创建页面、数据库、属性和 blocks；复杂 linked database 视图、模板按钮、精细筛选视图不作为 P0 强依赖。

## 7. 一键初始化流程

### 7.1 P0 流程

1. 用户创建或选择一个 Notion 父页面。
2. 用户把父页面共享给 wxreadmaster Integration。
3. 用户在应用设置页输入 Token 和父页面 ID。
4. 点击 `创建阅读库数据库`。
5. 应用在父页面下创建 `阅读成果库`。
6. 应用回填数据库 ID，默认目标切换为 `Database`。
7. 用户导出任意成果到 Notion。

### 7.2 已实现：首页式工作台流程

1. 应用先创建 `微信读书知识库` 首页。
2. 首页内创建导航说明 blocks。
3. 在首页下创建 `阅读成果库` 数据库。
4. 首页写入数据库链接和使用分区。
5. 应用返回首页 URL 和数据库 URL。

当前已由 `create_notion_reading_workspace_template` 落地。创建成功后，应用不会把默认导出目标指向首页，而是指向子级 `阅读成果库` 数据库，保证后续一键导出能直接进入可筛选的数据表。

兼容保留：`create_notion_reading_library_template` 仍可只创建数据库，适合已有 Notion 首页、只想手动配置数据库入口的用户。

## 8. API 边界

当前使用 Notion `2022-06-28` API 兼容路径，适合继续做 P0。

官方边界需要注意：

- 创建数据库需要父级 Notion 页面，且 Integration 需要 insert content 权限。
- Notion 2025-09-03 之后把 database 和 data source 概念拆开，后续升级时需要适配新 data source schema。
- 创建页面时可以写 properties、cover、icon 和 children blocks。
- 数据库行本质是页面，属性值必须符合父数据库或 data source 的 schema。

设计影响：

- P0 不依赖多 data source。
- P0 不强依赖复杂视图创建。
- 模板字段要尽量稳定，避免每次 Notion API 版本变化都迁移。
- 导入时只写存在且类型匹配的字段，用户删字段也不阻断正文导入。

参考：

- https://developers.notion.com/reference/create-database
- https://developers.notion.com/reference/post-page
- https://developers.notion.com/reference/data-source
- https://developers.notion.com/reference/page-property-values

## 9. 分阶段实现建议

### 阶段 1：成果数据库增强

目标：让当前所有可导出的成果在数据库里更可筛选。

任务：

- 写入 `Prompt 版本`、`输入哈希`。
- 从 `frontMatter` 写入 `Book ID`、`scope`、`mode/baseTime`。
- 书籍复盘写入 `标签`、`阅读阶段`、`行动数`。
- 阅读统计复盘写入 `周期`。
- 阅读路线和选书决策写入 `候选书数`。

### 阶段 2：首页式模板

目标：接近截图里的完整 Notion 前端体验。

已完成：

- 新增 `create_notion_reading_workspace_template`。
- 创建首页页面。
- 给首页写 icon、cover 和导航 blocks。
- 在首页下创建 `阅读成果库` 数据库。
- 返回首页 URL 和数据库 URL。

保留边界：

- 首页数据库链接追加失败时，不回滚已创建的首页和数据库，只返回 warning。
- Notion 默认导出目标保存为 `阅读成果库` 数据库 ID。
- 双目标导出时，后端会优先尝试 Obsidian 写入，再把成功路径写入 Notion 属性；即使调用方传入 `Notion + Obsidian` 顺序，返回结果仍按请求顺序展示。
- 复杂 linked database 视图仍不作为 API 初始化强依赖。

### 阶段 3：视图与模板页增强

目标：让 Notion 内部更像可直接使用的工作台。

任务：

- 支持用户复制官方 Notion 模板链接。
- API 初始化后提示用户创建推荐视图。
- 如 Notion API 能稳定支持视图管理，再自动创建过滤视图。

## 10. 取舍

推荐首版保持单数据库：

- KISS：一个数据库足够承接五类成果。
- YAGNI：不提前做关系库和同步状态机。
- DRY：所有成果共用 `ExportDocument` 和 Notion 目标适配器。
- SOLID：Notion 模板初始化、目标导出、凭据管理职责分离。

后续只有当用户明显需要“书籍档案库”和“行动任务库”时，再拆：

- `书籍库`：每本书一条，承载长期状态。
- `阅读成果库`：每次导出一条，关联书籍。
- `行动库`：行动项/复盘问题任务化。

目前不建议直接上三库结构，因为当前应用导出的最完整载体仍然是“成果页面”，不是结构化任务流。
