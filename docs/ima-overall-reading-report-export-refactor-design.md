# IMA 总计阅读报告导出改造设计

> **状态**：已实施（2026-08-19）
> **确认日期**：2026-08-18；实施完成：2026-08-19
> **范围**：阅读复盘页“总计/全部历史”报告导出到 IMA
> **不包含**：IMA 原生版本历史读取、应用内导出历史列表、远端旧笔记删除或覆盖、后台自动同步
> **上位文档**：[IMA 笔记与知识库导出设计](./ima-notes-knowledge-base-export-design.md)

## 1. 结论

总计阅读报告是长期阅读分析的核心产物，必须支持导出到 IMA。总计报告的数据会持续变化，不能套用“已结束周/月/年周期”的最终性判断，也不应更新同一篇远端笔记。

本次改造采用以下确定方案：

- 阅读复盘页的“总计/全部历史”模式显示 IMA 导出目标；
- 每次用户确认导出，都在 IMA 创建一篇新的带时间快照；
- 快照标题包含报告类型、导出时间和操作短标识；
- 即使正文内容哈希未变化，重复导出也创建新的总计快照；
- 旧快照保留在 IMA 中，不追加、不覆盖、不删除；
- 应用内不新增导出历史列表；
- 周/月/年报告继续使用现有“已结束周期 + 内容哈希去重”规则；
- 总计报告的导出说明明确提示“每次导出创建新快照，不覆盖旧版本”。

这使 IMA 成为总计阅读报告的时间序列归档位置。用户通过 IMA 笔记标题中的时间和正文快照时间追溯版本；本应用不承诺提供 IMA 原生版本历史查询。

## 2. 当前问题

当前实现把 `overall` 视为永远未结束的周期：

- 前端 `isCompletedReadingStatsPeriod` 对 `overall` 返回 `false`，阅读复盘页不把 IMA 加入可用目标；
- 后端 `is_completed_reading_stats_review` 对 `mode = "overall"` 直接返回 `false`；
- 后端错误提示将全部历史报告与当前周、月、年统一描述为“仍可能变化”；
- IMA 导出通用逻辑有内容哈希去重，同一份总计数据重复点击不会创建新快照；
- IMA 适配器没有原生版本历史读取接口，应用内也没有导出历史列表。

结果是：用户可以在应用中分析全部历史阅读数据，却不能把这份长期分析沉淀到 IMA，导出目标与真实使用场景不一致。

## 3. 设计目标

1. 总计阅读报告与周/月/年报告一样成为正式的 IMA 导出资产。
2. 总计报告每次主动导出都产生可识别、不可覆盖的 IMA 快照。
3. 不引入应用内历史列表、复杂版本管理页或新的后台任务中心。
4. 保留现有 IMA 凭据、正文授权、知识库关联、失败重试和未知状态恢复边界。
5. 不改变周/月/年、书籍复盘、阅读路线和选书决策的既有导出语义。
6. 让用户能在 IMA 中通过标题和正文元数据识别报告时间、来源和版本。

## 4. 非目标

- 不读取 IMA 的原生版本历史或编辑记录；当前 IMA 适配器没有稳定的版本历史 API。
- 不在应用内新增“IMA 导出历史”页面、列表或搜索功能。
- 不尝试更新、覆盖、追加到旧的总计报告笔记。
- 不自动删除旧 IMA 笔记，也不猜测用户是否已经在 IMA 手工编辑过内容。
- 不后台监听统计变化或自动向 IMA 发布新版本。
- 不把总计报告默认加入 IMA 知识库；是否关联知识库继续由导出配置和用户确认决定。

## 5. 资产与快照语义

### 5.1 资产身份

总计报告仍使用现有导出源类型：

```text
sourceKind = readingStatsReview
mode = overall
baseTime = 0
sourceId = overall:0
```

报告必须先在本地生成或读取有效的总计阅读复盘。没有统计数据或没有可导出的复盘结果时，导出流程在本地终止，不创建 IMA 空笔记。

### 5.2 标题与正文

沿用现有 IMA 快照序列化格式，标题示例：

```text
总计阅读报告 · 2026-08-18 21:30:15 +08:00 · A7F3C2
```

标题中的：

- 时间使用用户本地时区，精确到秒；
- 短标识来自本地 `operation_id` 的非敏感尾部；
- 不包含 API Key、Client ID 或原始正文哈希。

正文末尾保留结构化来源元数据：

```text
导出来源：WxReadMaster
资产类型：阅读统计复盘
来源 ID：overall:0
快照时间：2026-08-18 21:30:15 +08:00
```

### 5.3 每次导出都创建新快照

对总计报告，`force_new_snapshot` 的有效值固定为 `true`。用户每次在导出弹窗中完成正文发送确认并点击开始导出，都会执行一次新的 `import_doc`：

```text
总计快照 A：2026-08-18 10:00:00
总计快照 B：2026-08-18 21:30:15
```

即使 A 与 B 的稳定正文内容相同，也不能按普通资产的内容哈希去重。原因是用户的导出动作本身代表一次明确的历史观察点，快照标题和时间仍有追溯价值。

普通资产保持原规则：

| 资产 | 内容未变化 | 内容变化 |
| --- | --- | --- |
| 书籍笔记、书籍复盘、路线、选书决策、周/月/年复盘 | 复用本地成功记录并跳过远端请求 | 创建新快照 |
| 总计阅读报告 | 每次创建新快照 | 创建新快照 |

失败重试不产生第二个版本。对同一个 `operation_id`，重试必须继续使用已冻结的本地快照，避免网络超时后产生重复正文。

### 5.4 旧版本与知识库

- 旧 IMA 笔记不被覆盖、追加或删除；
- 用户选择关联知识库时，每个总计快照都按当前配置独立关联；
- 如果关联失败，保留已创建的 IMA 笔记并沿用 `partial` / `unknown` 语义；
- 旧快照可能继续存在于知识库检索范围内，界面和结果提示不得声称“已替换旧版本”；
- 用户需要清理旧快照时，前往 IMA 手动处理。

## 6. 用户体验改造

### 6.1 阅读复盘页

当当前模式为“总计/全部历史”时：

- 导出弹窗的可用目标包含 `Markdown`、`Obsidian`、`Notion`、`IMA`；
- IMA 目标说明改为：“每次导出创建带时间的历史快照，不覆盖旧版本”；
- 不再显示“IMA 仅支持已结束的周/月/年周期复盘”；
- 周/月/年仍按“仅已结束周期可导出到 IMA”展示；
- Web 只读预览继续禁止真实 IMA 写入。

### 6.2 导出确认

总计报告选择 IMA 后，继续要求用户显式确认正文发送：

```text
我确认：本次总计阅读报告正文和统计结论将发送到 IMA，且每次导出都会创建新的历史快照。
```

确认只对当前导出弹窗有效。关闭弹窗、取消 IMA 或完成一次导出后，下次必须重新确认。

### 6.3 成功态

成功结果至少显示：

- IMA 快照标题；
- 导出时间；
- 是否已关联知识库；
- 远端笔记 ID 或知识库资料 ID（不展示凭据）；
- “旧快照未修改”的说明。

不增加应用内历史列表，也不把本地内部 `operation_id` 作为用户必须复制的操作项；标题中的短标识仅用于在 IMA 中人工区分同秒导出。

### 6.4 失败与恢复

| 状态 | 用户看到的行为 | 处理规则 |
| --- | --- | --- |
| 本地无统计或无复盘 | 禁止提交 IMA 导出 | 不发起远端请求 |
| 正文发送前失败 | 显示本地错误 | 可重新发起一次新导出 |
| 创建笔记失败且结果明确 | 显示失败 | 可重新发起新导出 |
| 创建笔记超时、结果未知 | 显示未知状态 | 先检查远端或由用户决定放弃/创建新快照 |
| 知识库关联失败 | 显示部分成功 | 保留已创建笔记，允许重试关联或创建新快照 |
| 重试同一个操作 | 恢复原快照 | 不创建额外版本 |

## 7. 实现边界

### 7.1 前端

修改范围：

- `src/pages/reading-stats-period.ts`
  - `isCompletedReadingStatsPeriod({ mode: "overall" })` 改为返回 `true`；
  - 周/月/年判断保持不变。
- `src/pages/ReadingReviewPage.tsx`
  - IMA 可用目标基于“总计或已结束周期”判断；
  - 导出说明按 `overall` 与周期模式分别显示；
  - 保持现有 `exportReview` 调用链，不新增历史状态。
- 相关测试和 E2E mock
  - 总计模式下可见 IMA 目标；
  - 当前周/月/年仍按既有规则隐藏 IMA；
  - 总计导出请求携带 `mode = overall`、`baseTime = 0` 和强制新快照标志。

### 7.2 Rust 导出服务

修改范围：

- `src-tauri/src/export/ima.rs`
  - `is_completed_reading_stats_review` 对 `overall + baseTime=0` 返回 `true`；
  - 非 `overall` 周/月/年仍必须是已结束周期；
  - 总计报告将 `force_new_snapshot` 固定为 `true`；
  - 继续使用 `import_doc` 创建新笔记，不调用不存在的覆盖接口。
- `src-tauri/src/export/document.rs`
  - 不新增导出源类型，继续复用 `ReadingStatsReview`。
- `src-tauri/src/repositories/ima_exports.rs`
  - 不改变数据库结构；
  - 总计相同 `content_hash` 的导出不再命中普通成功记录；
  - 相同操作的恢复和失败重试仍复用冻结快照。

### 7.3 IMA 客户端边界

沿用现有接口：

- `openapi/note/v1/import_doc`：创建总计快照；
- `openapi/note/v1/append_doc`：处理超过单次正文限制的分块；
- `openapi/wiki/v1/add_knowledge`：用户选择知识库时关联快照；
- 现有定位、漂移检查和未知状态恢复逻辑继续适用。

不新增远端版本查询，因为当前 IMA 客户端没有稳定的历史版本接口。

## 8. 数据与安全边界

- 总计报告只发送当前生成的结构化统计复盘和报告正文，不发送原始笔记正文；
- 正文发送前必须有显式用户确认；
- API Key、Client ID、数据库路径、内部诊断信息不进入 IMA 正文、标题或日志；
- 总计快照内容由本地 `ExportDocument` 和 Markdown 序列化结果决定，IMA 不作为本地事实源；
- 删除本地 IMA 凭据不会删除远端快照；
- Web 只读预览不允许真实 IMA 写入。

## 9. 测试方案

### 9.1 单元测试

- `isCompletedReadingStatsPeriod`：`overall` 为 `true`，当前周/月/年仍为 `false`，已结束周期仍为 `true`；
- `is_completed_reading_stats_review`：`overall + baseTime=0` 为 `true`，非法模式和非法 baseTime 为 `false`；
- IMA 标题包含总计报告名称、导出时间和操作短标识；
- 总计报告的相同正文重复开始导出时，仓储层仍创建新记录；
- 同一个 `operation_id` 重试时仍复用原快照，不创建第二条记录；
- 总计报告的快照正文包含 `mode=overall` 对应的来源信息。

### 9.2 前端与 E2E

- 总计模式打开导出弹窗时可见 IMA；
- 总计模式不再显示“仅支持已结束周期”的错误说明；
- 当前周期仍不可选择 IMA；
- 未生成复盘时，IMA 导出仍被禁止；
- 总计导出确认后请求包含 `overall` 和强制新快照语义；
- 连续两次总计导出展示两个不同的 IMA 快照标题；
- Web 只读预览仍不会执行 IMA 写入。

## 10. 验收标准

| 场景 | 预期结果 |
| --- | --- |
| 总计报告已生成，选择 IMA | IMA 可选，确认后创建带时间的新快照 |
| 总计报告重复导出且内容未变 | 创建新的 IMA 快照，不被内容哈希去重 |
| 总计报告内容发生变化后导出 | 创建新的 IMA 快照，旧快照保留 |
| 周/月/年当前周期 | IMA 仍不可选 |
| 周/月/年已结束周期 | IMA 仍按旧逻辑导出并去重 |
| IMA 创建结果未知 | 不自动创建第二个版本，先进入检查/人工决策 |
| 关联知识库失败 | 保留 IMA 笔记，显示部分成功，不声称替换旧版本 |
| 用户查看 IMA | 可以从标题时间和正文快照时间区分多个总计版本 |
| 用户查看应用 | 不出现新的导出历史列表，不增加版本管理入口 |

## 11. 迁移与发布

- 不需要数据库迁移；现有 IMA 导出记录和远端笔记保持不变；
- 已存在的总计导出记录若有，后续总计导出按新规则强制创建新快照；
- 周/月/年和其他资产不改变去重、恢复和远端漂移语义；
- 发布说明应明确：总计阅读报告现在支持 IMA 历史快照导出，每次导出不会覆盖旧版本；
- 首次发布后重点观察 IMA 重复快照数量、未知状态处理和用户是否误解“导出”与“更新”的区别。

## 12. 设计裁决

本方案明确放弃“更新同一篇 IMA 总计报告”的路线。当前 IMA 公开接口只有创建和追加能力，追加会把多个统计时点混在同一篇笔记中，既无法形成可读版本边界，也无法可靠回滚。因此，带时间的独立快照是当前接口条件下最简单、可解释、可恢复的产品语义。
