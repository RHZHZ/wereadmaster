# 长期阅读画像导出面板设计

> **状态**：v1.0.17 已按上位共享框架实施；本文保留长期阅读画像 / 周期复盘页面级规格
> **范围**：长期阅读画像 / 周期复盘页面的 Markdown、Obsidian、Notion 文档导出
> **不包含**：报告图片生成、下载、保存到相册、分享，以及其他页面导出入口的同步改造
> **上位实现框架**：`unified-export-interaction-refactor-design.md`；共享组件、状态模型和迁移顺序以上位文档为准
> **依据**：`functional-consolidation-blueprint.md`、`bulk-export-wizard-layout.md`、现有 `MultiTargetExportRequest` / `MultiTargetExportResponse` 契约
> **产品裁决**：2026-08-02
> **实施更新**：2026-08-04

## 1. 摘要

实施前，长期阅读画像页面在同一操作区同时提供“导出到”下拉框和“一键导出”按钮。两者并非代码层面的完全重复：下拉框选择目标，按钮执行导出；但组合后的交互存在三个问题：

1. **操作顺序不自然**：用户需要先理解并操作下拉框，再点击所谓“一键”按钮。
2. **命名承诺不准确**：点击按钮本身不会立即导出，目标仍由另一个控件决定，因此不是真正的一键导出。
3. **承载能力不足**：目标配置、未配置提示、多个目标、部分成功、失败和重试无法在紧凑工具栏内清楚表达。

本设计将页面入口收敛为一个按钮：**“导出报告”**。点击后打开导出面板，在面板中完成本次导出目标选择、配置状态确认、执行和结果查看。

长期配置继续由设置页负责：

- Markdown 导出目录；
- Obsidian Vault 与相关导出设置；
- Notion 凭据、父级页面/数据库、数据库连接和字段映射。

导出面板只读展示当前配置，不提供“更改保存位置”或其他长期设置编辑。配置缺失或失效时，面板可以提供“前往设置”恢复入口，但不在弹窗内复制设置流程。

## 2. 背景与现状

### 2.1 当前页面行为

实施前 `ReviewHeroSection` 的操作区大致为：

```tsx
<button onClick={onExport}>
  {isExporting ? "导出中" : "一键导出"}
</button>

<label>
  <span>导出到</span>
  <select value={exportDestination}>
    <option value="markdown">Markdown</option>
    <option value="obsidian">Obsidian</option>
    <option value="notion">Notion</option>
    <option value="obsidianNotion">Obsidian + Notion</option>
  </select>
</label>
```

`useReadingReviewPage.handleExport` 当前根据单个 `ExportDestination` 转换目标，再调用 `exportReadingStatsReviewTargets`。底层类型已经具备更适合新交互的能力：

```ts
export type MultiTargetExportRequest = {
  targets: ExternalExportTarget[];
  obsidian?: { vaultDir?: string; openAfterExport?: boolean };
  notion?: { parentId?: string; parentType?: NotionParentType };
};
```

返回值按目标提供结果：

```ts
export type MultiTargetExportResponse = {
  exportId: string;
  sourceKind: ExportSourceKind;
  sourceId: string;
  exportedAt: string;
  results: ExportTargetResult[];
};
```

因此，新面板不应继续维护 `obsidianNotion` 这种组合枚举，而应直接使用目标数组：用户同时勾选 Obsidian 和 Notion，即形成两个目标。

### 2.2 设置页已经承担长期配置

`SettingsPage` 已有独立的“导出保存位置”设置区，并负责：

- 选择、输入、保存和恢复默认 Markdown 导出目录；
- 选择和保存 Obsidian Vault；
- 保存 Notion 导出设置；
- 保存 Notion 数据库连接、父级和字段映射。

如果导出面板再次提供“保存到：默认导出目录 + 更改”，就会造成设置职责重复，并让用户误以为目录是本次导出的临时参数。这个设计明确不采用该方案。

## 3. 产品目标与非目标

### 3.1 目标

- 页面只保留一个明确的文档导出入口。
- 让用户在执行前看清本次导出的目标和目标状态。
- 支持 Markdown、Obsidian、Notion 的单选或多选。
- 复用现有目标级结果契约，清晰表达成功、失败、跳过和警告。
- 长期设置只有一个管理入口，即设置页。
- 导出失败后保留用户选择，允许修复设置后重试。
- 桌面、移动端和 Web 预览对能力边界说真话。

### 3.2 非目标

本轮不做以下事情：

- 不改造报告图片生成向导；
- 不把“生成报告图片”“下载图片”“保存到相册”“分享图片”并入文档导出面板；
- 不同步改造 `ReadingRoutePage`、`BookDecisionPage` 或批量导出向导的工具栏；
- 不在导出面板内编辑导出目录、Vault、Notion 凭据、数据库或字段映射；
- 不新增导出目标；
- 不自动生成缺失的 AI 复盘；
- 不因为打开导出面板而自动连接 Notion、自动同步远端数据或自动创建数据库；
- 不把 Web 只读预览伪装成可执行导出环境。

## 4. 核心产品裁决

### 4.1 页面入口

页面操作区改为：

```text
[同步统计] [导出报告]
```

按钮文案状态：

| 状态 | 文案 | 说明 |
| --- | --- | --- |
| 可导出 | 导出报告 | 点击打开导出面板，不直接执行导出 |
| 正在导出 | 导出中 | 可保留在按钮或仅在面板中展示；按钮不可重复触发 |
| 当前无复盘 | 导出报告 | 按现有禁用规则禁用，并显示已有的不可导出原因 |
| Web 只读预览 | 导出报告 | 不执行导出；打开面板后说明“请在桌面应用中执行” |

不再使用“一键导出”。点击入口后的第一步仍需选择目标，因此“导出报告”更准确。

### 4.2 面板职责

导出面板只负责四件事：

1. 说明本次导出的资产范围；
2. 选择本次导出目标；
3. 只读确认长期配置是否可用；
4. 执行导出并展示目标级结果。

面板不负责维护长期配置，不应出现以下控件：

- “更改保存位置”；
- “选择 Vault”；
- Notion Token 输入框；
- Notion 数据库字段映射编辑器；
- 在面板内创建或替换标准数据库的复杂流程。

### 4.3 目标选择

使用三个独立的多选目标：

| 目标 | 默认状态 | 只读配置摘要 | 适用平台 |
| --- | --- | --- | --- |
| Markdown | 默认选中 | `保存到：<当前导出目录>` | 桌面 |
| Obsidian | 默认不选中 | `Vault：<当前 Vault>` | 桌面 |
| Notion | 默认不选中 | `数据库：<当前数据库名称或未配置>` | 桌面 |

`Obsidian + Notion` 不再作为第四个选项。组合导出由多选自然表达。

默认选中 Markdown 的理由：它是本地兜底目标，依赖最少；用户打开面板后可以直接点击“开始导出”，但仍然清楚知道目标是什么。因此这是“少一步确认”，不是对外宣称“一键”。

如果产品后续需要记忆用户最近选择，可以新增全局 `settings.exportTargetPreference`；本轮实现可以先使用 Markdown 默认选中，不强制引入新的偏好持久化。

## 5. 面板信息架构

### 5.1 面板标题区

```text
导出报告
长期阅读画像 · 月度复盘
```

标题下展示本次资产范围：

- 周度 / 月度 / 年度 / 全部历史；
- 统计周期文本；
- 资产状态：已生成的周期复盘；
- 可选的生成时间或缓存状态。

这里的“报告”是文档导出资产的统称；分享图片仍称“报告图片”，不在本面板中混用。

### 5.2 目标选择区

每个目标使用可点击的选择卡，而不是原生紧凑下拉框。卡片包含：

```text
[✓] Markdown
    保存到：C:\...\exports
    已配置
```

```text
[ ] Obsidian
    Vault：D:\...\Obsidian
    已配置
```

```text
[ ] Notion
    数据库：阅读成果库
    已连接
```

选择卡必须支持键盘操作和明确的选中状态。目标卡的选择与配置状态分离：

- 配置正常：可以选中；
- 配置缺失：仍可以查看，但不能进入执行；显示“未配置”；
- 配置失效：可以查看，显示“配置需要更新”；
- Web 预览：目标卡全部只读，显示“桌面应用可用”。

### 5.3 配置摘要规则

配置摘要只读，不显示秘密信息，不显示完整 Token。

#### Markdown

正常：

```text
保存到：<当前导出目录>
```

异常：

```text
未读取导出目录
前往设置
```

目录过长时使用中间省略或末尾省略，但必须保留可访问名称中的完整文本。不得展示“默认导出目录”作为唯一信息，除非当前目录确实就是默认目录；当前目录是用户判断实际落点的事实来源。

#### Obsidian

正常：

```text
Vault：<Vault 名称或路径>
```

异常：

```text
尚未配置 Obsidian Vault
前往设置
```

Vault 路径失效时使用“Vault 不可用”，不要假装它仍可写入。

#### Notion

正常：

```text
数据库：<数据库名称>
连接：已连接
```

异常：

```text
尚未配置 Notion 目标
前往设置
```

凭据存在但数据库连接不完整时，显示具体的恢复方向，例如“需要完成数据库字段映射”。不在面板中展开设置流程。

### 5.4 底部操作区

选择态底部固定显示：

```text
[取消]                         [开始导出]
```

规则：

- 未选择任何目标时，“开始导出”禁用，并提示“至少选择一个导出目标”；
- 选择了未配置目标时，“开始导出”禁用，并在目标卡内指出问题；
- 选择 Markdown 且配置正常时可执行；
- 执行期间禁用目标选择、关闭按钮和“开始导出”，防止重复提交；
- 取消只关闭面板，不撤销已经完成的目标写入。

如果用户只想使用已配置目标，应在卡片上取消问题目标；如果用户要修复问题，应点击“前往设置”。

## 6. 状态模型

建议将面板状态建模为两类：面板阶段和导出运行状态，避免多个布尔值组合出非法状态。

```ts
type ReadingReviewExportPanelStage = "select" | "result";

type ReadingReviewExportRunState =
  | "idle"
  | "running"
  | "succeeded"
  | "partial"
  | "failed";

type ReadingReviewExportTargetState = {
  target: ExternalExportTarget;
  selected: boolean;
  readiness: "ready" | "missing" | "invalid" | "readonly";
  destinationLabel: string;
};
```

面板初始打开时为 `select + idle`。调用导出后切换为 `select + running`，导出响应返回后切换为 `result`，根据 `results` 计算 `succeeded`、`partial` 或 `failed`。

### 6.1 选择态

展示：

- 资产范围；
- 三个目标卡；
- 只读配置摘要；
- 配置异常提示；
- 取消和开始导出。

### 6.2 执行态

展示：

```text
正在导出
已提交 2 个目标，请稍候……
```

如果底层只返回整体 Promise，不提供进度事件，本轮不要伪造百分比或“正在写入第 N 个目标”。可以显示目标级静态状态“处理中”。

### 6.3 结果态

顶部显示汇总：

- 全部成功：`已导出到 2 个目标`；
- 部分成功：`已完成 1 个目标，1 个目标失败`；
- 全部失败：`导出未完成`；
- 全部跳过：`没有写入新的内容`。

下面逐目标展示结果：

| 状态 | 展示 | 操作 |
| --- | --- | --- |
| succeeded | 目标名称、路径或 URL、文件数、警告 | 打开位置 / 打开页面（若能力支持） |
| failed | 目标名称、错误分类、恢复建议 | 前往设置 / 重试 |
| skipped | 目标名称、跳过原因 | 根据原因决定是否返回设置 |

失败结果不能只放在 toast 中。toast 可以作为辅助反馈，但结构化结果必须留在面板内。

底部操作：

```text
[关闭] [返回选择] [重试失败目标]
```

- 全部成功时可只显示“关闭”；
- 部分成功时显示“关闭”和“重试失败目标”；
- 全部失败时显示“返回选择”和“重试”；
- 返回选择保留原目标选择，不清空用户状态；
- 重试失败目标只提交失败目标，除非底层接口不支持目标级重试，此时提交原选择并在实现中避免重复写入已成功目标。

## 7. 目标级错误与恢复

### 7.1 未配置

示例：

```text
Notion 尚未配置导出目标。
请在设置页完成连接和数据库配置。
[前往设置]
```

“前往设置”应关闭导出面板或将其置于后台，记录来源上下文。用户返回后重新打开面板时重新读取配置状态，不复用旧的“未配置”快照。

### 7.2 配置失效

例如导出目录被删除、Vault 不可访问、Notion 数据库被撤销访问。文案应区分：

- 找不到目录：`当前导出目录不可用`；
- 无权限：`当前导出目录没有写入权限`；
- Notion 授权失败：`Notion 连接已失效`；
- 数据库映射不完整：`Notion 数据库配置未完成`。

每类错误都给出恢复建议，但不在导出面板内编辑配置。

### 7.3 部分成功

多目标导出是目标级独立结果。Obsidian 成功而 Notion 失败时：

- 不把整个操作显示为“失败”；
- 顶部明确显示“部分完成”；
- 保留 Obsidian 成功路径；
- 只对 Notion 提供重试或前往设置；
- 不要求用户为了重试 Notion 再次导出已成功的 Obsidian，除非底层接口暂不支持单目标重试；
- 警告不能覆盖成功状态。

### 7.4 顶层命令失败

如果导出命令在返回目标结果前整体失败，使用结构化错误面板，至少包含：

1. 错误分类标题；
2. 可读错误说明；
3. 恢复建议；
4. 当前目标选择仍被保留；
5. “重试”和“返回选择”。

不自动重试，不自动同步远端，不自动创建 Notion 数据库。

## 8. 平台边界

### 8.1 桌面应用

桌面应用提供完整能力：

- 读取设置页中的导出目录、Vault 和 Notion 连接；
- 执行 Markdown、Obsidian、Notion 导出；
- 在能力支持时打开文件位置或 Notion 页面；
- 展示真实错误和目标级结果。

### 8.2 移动端

移动端沿用同一信息架构，但面板改为底部面板或接近全屏的对话框：

- 目标卡纵向排列；
- 路径摘要允许多行或末尾省略；
- 底部主按钮固定在安全区域内；
- 不产生横向溢出；
- 若某目标在移动端不可执行，明确显示“桌面应用可用”，不能渲染成可点击后再失败。

### 8.3 Web 只读预览

Web 预览只展示报告和导出面板的能力说明，不调用桌面导出命令：

```text
当前为 Web 只读预览
导出报告请在桌面应用中执行。
```

可以允许用户查看目标配置卡的占位状态，但不能伪造本地目录、Vault 或 Notion 连接状态。

## 9. 可访问性与交互细节

- 面板使用 `role="dialog"`、`aria-modal="true"`，提供唯一且准确的 `aria-label="导出报告"`。
- 打开面板时保存触发按钮，焦点移动到标题或第一个可交互目标。
- `Tab` 顺序：关闭 → 目标卡 → 前往设置链接 → 取消 → 开始导出；结果态按结果卡顺序移动。
- `Esc` 在选择态和结果态关闭面板；执行态不允许关闭，避免用户误以为可以取消后台写入。
- 关闭后焦点恢复到“导出报告”按钮。
- 目标卡不能只依赖颜色表达选中或错误，必须有勾选、状态文本和可访问名称。
- 路径和 URL 具有可读的完整 `aria-label`；视觉截断不应丢失信息。
- 运行中按钮设置 `aria-busy="true"`，并禁用重复提交。
- 结果状态使用文本和图标双重表达；错误区域可使用 `role="alert"`，但不让屏幕阅读器重复播报整张结果列表。

## 10. 数据契约与实现边界

### 10.1 请求

面板负责把多选目标转换为现有 `MultiTargetExportRequest`：

```ts
const request: MultiTargetExportRequest = {
  targets: selectedTargets
};
```

如果现有命令需要把已读取的配置显式传入，可以补充：

```ts
const request: MultiTargetExportRequest = {
  targets: selectedTargets,
  obsidian: selectedTargets.includes("obsidian")
    ? { vaultDir: settings.obsidian.vaultDir }
    : undefined,
  notion: selectedTargets.includes("notion")
    ? {
        parentId: settings.notion.parentId,
        parentType: settings.notion.parentType
      }
    : undefined
};
```

但配置的权威来源仍是设置状态与后端持久化配置。面板不应把临时输入写回设置。

### 10.2 响应

直接消费 `MultiTargetExportResponse.results`，按 `target` 映射到结果卡。不要依据 toast 文案推断结果，也不要把 `obsidianNotion` 作为新的响应目标类型。

### 10.3 兼容性

如果现有 `ExportDestination` 被其他页面继续使用，可以暂时保留类型以避免无关页面回归；长期阅读画像页面应移除对该单值 UI 状态和 `obsidianNotion` 选项的依赖。

旧的页面正文结果列表应迁入导出面板结果态，避免页面内容和弹窗同时显示两份不同结果。过渡阶段如必须保留页面摘要，只保留最近一次导出的一行摘要，并提供“查看详情”重新打开结果面板，不再重复渲染完整结果列表。

## 13. 分阶段落地与回滚

### 13.1 落地顺序

1. 先新增面板并以现有导出命令为后端，不改变目标能力。
2. 再把 `ReviewHeroSection` 的旧下拉框替换为单一入口。
3. 再迁移页面正文结果列表到面板结果态。
4. 最后补充配置状态读取、移动端布局、Web 边界和可访问性。
5. 所有 E2E 通过后，再考虑是否移除长期画像专用的旧单值状态代码。

### 13.2 回滚策略

- 组件级回滚：恢复 `ReviewHeroSection` 的旧入口，但保留底层多目标契约不变。
- 数据级无需迁移：本设计不新增持久化表，也不改变已有导出结果结构。
- 设置级不回滚：设置页仍是唯一长期配置入口，不因面板回滚而重新加入弹窗配置编辑。
- 如果新面板只在特定平台出现问题，可以按平台关闭面板入口，保留原有报告图片能力，不影响报告查看和生成。

## 14. 实施验收结论

v1.0.17 实施后，用户在长期阅读画像页面的心智路径为：

```text
查看周期复盘
  → 点击“导出报告”
  → 选择一个或多个目标
  → 确认只读目的地状态
  → 开始导出
  → 查看每个目标的真实结果
```

设置问题回到设置页解决，单次目标选择留在导出面板解决，报告图片交付留在报告图片向导解决。三者职责不重叠，且任何导出失败都有明确的结果和恢复路径。
