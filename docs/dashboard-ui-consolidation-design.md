# 阅读总览 UI 去重与层级收口设计文档

## 1. 文档信息

- 适用页面：`DashboardPage`
- 实现入口：`src/pages/DashboardPage.tsx`
- 动作模型：`src/pages/dashboard-workbench-actions.ts`
- 今日卡片模型：`src/pages/dashboard-daily-card.ts`
- 本地进展模型：`src/pages/dashboard-local-progress.ts`
- 样式入口：`src/styles.css`
- 设计阶段：总览 P0/P1 信息架构收口
- 目标主题：浅色、深色、紧凑密度
- 设计目标：删除重复模块、压缩首屏、稳定“今天做什么”的主叙事

## 2. 背景

当前阅读总览已经完成从简单统计页向“每日阅读工作台”的多轮演进，具备：

- 微信读书连接和同步状态。
- 今日主动作与备选动作。
- 最近阅读与书架概况。
- 今日卡片。
- 本地阅读资产进展。
- 阅读人格、下周期建议和推荐书籍。
- 继续读、待复盘和本地候选队列。

这些模块分别有明确价值，但旧结构在新增能力后没有同步退出，导致首页同时存在多组语义相近的信息：

- `DailyWorkbenchPanel` 已展示一个主动作和最多两个备选动作，后面仍有完整 `today-actions-panel`。
- `WereadOverviewCard` 已展示最近 5 本电子书，页面底部 `activity-panel` 又展示最近 3 本内容。
- `DashboardLocalProgressPanel` 汇总已整理、待复盘、候选和笔记书数量，`dashboard-queue-panel` 又按相同语义展示明细。
- Hero 快捷入口、最近阅读操作、本地队列空态和底部书架操作重复提供书架、笔记、复盘等入口。

问题已经不是功能不足，而是页面缺少严格的退出机制。继续增加模块或只调整颜色、圆角和阴影，无法解决根因。

本次以当前实现为基线，只做信息架构去重、视觉层级收口和状态布局调整，不重写业务模型，不新增后端能力。

## 3. 设计上下文

### 3.1 目标用户

- 使用微信读书并希望在桌面端管理个人阅读资产的用户。
- 已拥有书架、阅读进度、笔记、候选和复盘数据，需要每天快速判断下一步。
- 既包含刚连接、尚未同步的用户，也包含拥有大量本地缓存的长期用户。

### 3.2 核心使用场景

按优先级排序：

1. 打开应用后确认今天最值得做的一件事。
2. 回到最近阅读现场，继续推进一本书。
3. 查看待复盘、已整理和候选书的本地状态。
4. 消费一条有来源的阅读建议或成果入口。
5. 在需要时进入书架、笔记、复盘、统计和发现等完整页面。

### 3.3 品牌与视觉语气

采用“克制、温和、可信、行动导向”的个人阅读工作台风格：

- 不做营销首页，不依赖大幅 Hero 制造价值感。
- 不把统计数字当装饰性主角。
- 不用相同圆角卡片承载所有信息。
- 通过内容顺序、空间、边界和操作权重形成层级。
- 页面首先回答“今天做什么”，其次才展示资产和洞察。

### 3.4 核心产品定义

> 让用户每天打开应用后，在 3 分钟内明确一个阅读动作，并带走一个可见成果。

首页的价值必须归入以下至少一类：

- 行动：现在读什么、整理什么。
- 决策：继续读、复盘或选择下一本。
- 交付物：获得可复制、可导出或可继续加工的成果。

统计、画像、推荐和同步状态只能作为证据或辅助信息，不能与主动作竞争。

## 4. 目标

### 4.1 用户体验目标

1. 用户进入已连接状态的首页后，2 秒内识别唯一主动作。
2. 首屏能同时看到今日主动作和最近阅读模块的开头。
3. 同一类信息只保留一个主展示位置。
4. 首页不再出现两套最近阅读或两套今日动作。
5. 本地进展既能提供规模上下文，又不重复队列明细。
6. 阅读人格、周期建议和推荐书籍保持可发现，但不抢主流程。
7. 无凭据、无书架、无最近阅读、无队列和局部错误时均有单一恢复路径。

### 4.2 工程目标

- 复用现有 `buildTodayActions()`、`buildDailyWorkbenchActions()` 和今日卡片模型。
- 不改变最近阅读筛选、排序和最多 5 本的规则。
- 不新增 Tauri 命令、数据库字段或后台自动同步。
- 不自动读取单本笔记正文。
- 不自动调用 AI。
- 优先通过 JSX 删除、模块合并和局部 CSS 调整完成。
- 更新单测和 E2E，删除对废弃模块的断言。

## 5. 非目标

本轮不做：

- 不重做全局导航。
- 不把总览改造成完整书架页。
- 不新增阅读打卡、积分、等级或成就系统。
- 不新增统计图表、趋势图或排行榜。
- 不新增推荐算法或自动 AI 生成。
- 不重做阅读人格模型。
- 不重做笔记中心、单本笔记页和单本复盘页。
- 不新增首页自定义组件开关或拖拽布局。
- 不改变 `organized` 的显式触发规则。
- 不因本轮 UI 调整修改导出链路和文件格式。

## 6. 当前实现基线

当前已连接状态的页面顺序为：

```text
阅读总览
├─ 阅读工作台 Hero
│  ├─ 产品说明
│  └─ 书架 / 笔记 / 复盘 / 发现快捷入口
├─ 三项核心指标
│  ├─ 书架条目
│  ├─ 公开 / 私密
│  └─ 最近同步
├─ 连接状态条
├─ 今日阅读工作台
│  ├─ 今日最值得做
│  └─ 最多两个备选动作
├─ 微信读书概况 / 最近阅读
├─ 今日可做 / 辅助动作完整列表
├─ 今日卡片
├─ 本地进展
├─ 阅读人格 / 下周期建议 / 推荐书籍
├─ 本地阅读队列
│  ├─ 继续读
│  ├─ 待复盘
│  └─ 本地候选
└─ 继续阅读 / 最近打开的内容
```

已有合理实现继续保留：

- `DailyWorkbenchPanel` 的一个主动作和最多两个备选动作。
- 主动作包含“为什么现在做”和“完成后得到”。
- `WereadOverviewCard` 只取最近 5 本电子书，按 `lastReadAt` 倒序。
- 最近阅读不会自动批量读取全部书籍详情。
- 今日卡片只使用已有本地数据，不自动调用 AI。
- 本地队列区分继续读、待复盘和本地候选。
- 阅读人格明确说明是阅读风格隐喻，不代表真实心理人格。
- 未连接状态不依赖远端内容，能够引导设置。

## 7. 核心问题

### 7.1 今日动作重复

`DailyWorkbenchPanel` 已承担今日决策：

- 一个最高优先级主动作。
- 最多两个备选动作。

但后续 `today-actions-panel` 又把完整 `todayActions` 列表作为大面板展示。

影响：

- 用户需要重复阅读同一动作池。
- 主动作的唯一性被削弱。
- 页面从“替用户做选择”退回“让用户继续比较多个入口”。
- 首屏高度被重复动作消耗。

### 7.2 最近阅读重复

`WereadOverviewCard` 与底部 `activity-panel` 使用接近的数据来源：

- 前者最多显示最近 5 本电子书。
- 后者显示最近 3 本可继续推进的内容。

影响：

- 用户在同一页看到两组相近书目。
- “最近阅读”缺少唯一主位置。
- 底部重复同步、查看书架等操作。
- 页面长度被无价值增加。

### 7.3 本地进展与队列语义重叠

`DashboardLocalProgressPanel` 展示：

- 已整理书籍。
- 待复盘书籍。
- 本地候选。
- 已同步笔记书。

`dashboard-queue-panel` 又展示继续读、待复盘和候选书明细。

影响：

- 指标与明细被拆成两个完整大容器。
- 页面形成连续大卡片，缺少主次节奏。
- 用户需要在摘要和队列间重复建立同一心智模型。

### 7.4 Hero 与实际主任务竞争

当前 Hero：

- 最小高度约 430px。
- 占据两列布局中的主列并跨两行。
- 包含四个快捷入口。
- 三项大指标位于右侧。

Hero 对初次理解产品有帮助，但对已连接的高频用户价值较低。首页真正的“今日最值得做”被放在 Hero、指标和状态条之后。

影响：

- 首屏先展示品牌说明和导航，而不是今日任务。
- 大图和大数字比主动作更抢眼。
- 长期用户每天重复消费相同静态说明。

### 7.5 洞察与推荐并列过多

阅读人格、下周期建议和推荐书籍同时占据首页洞察区。三者并非同等重要：

- 下周期建议能直接支持行动。
- 阅读人格主要提供解释和趣味。
- 推荐书籍与当前阅读推进关系最弱，已有独立发现页承接。

并列展示会让洞察区再次变成三个等权卡片。

### 7.6 万物皆卡片

Hero、指标、状态、今日主卡、最近阅读、辅助动作、今日卡片、本地进展、洞察、队列和底部最近阅读几乎都有完整边界、圆角和表面背景。

单个组件没有明显视觉错误，但整体形成模板化的“卡片瀑布”：

- 所有模块都在争取独立性。
- 空间分组无法表达优先级。
- 页面更像功能目录，而不是一个连续工作流。

## 8. 设计原则

### 8.1 一屏一个主任务

已连接状态下，首页唯一主任务是“今日最值得做”。

- 只允许一个主动作。
- 备选动作最多两个。
- 不再展示完整今日动作列表。

### 8.2 同类信息只有一个主位置

- 最近阅读只保留 `WereadOverviewCard`。
- 今日动作只保留 `DailyWorkbenchPanel`。
- 本地进展摘要并入本地队列，不再独占一个大面板。

### 8.3 行动优先于说明和指标

已连接用户不需要每天先阅读产品介绍。主动作必须进入首屏最高位置。

### 8.4 摘要服务明细

本地进展指标应作为队列的上下文，而不是与队列并列的完整模块。

### 8.5 洞察按行动价值排序

优先级：

1. 下周期建议。
2. 阅读人格。
3. 推荐书籍。

推荐书籍在没有明确首页价值时应回归发现页。

### 8.6 删除优先于新增

如果页面过长或层级不清，优先删除重复内容，不新增折叠面板、标签页、轮播或更多导航。

### 8.7 保持真实数据边界

- 不编造阅读目标。
- 不自动读取笔记正文。
- 不自动调用 AI。
- 不把画像当心理结论。
- 不把复制、导出或生成自动视为已整理。

## 9. 推荐信息架构

### 9.1 已连接且有书架数据

```text
阅读总览
├─ 紧凑页头
│  ├─ 阅读工作台
│  ├─ 一句当前状态说明
│  └─ [同步书架] [查看书架]
├─ 今日阅读工作台
│  ├─ 今日最值得做
│  ├─ 为什么现在做
│  ├─ 完成后得到
│  └─ 最多两个备选动作
├─ 最近阅读
│  ├─ 最近 5 本电子书
│  ├─ 刷新进度
│  └─ 查看书架
├─ 今日卡片
├─ 本地阅读队列
│  ├─ 轻量进展摘要
│  │  └─ 已整理 · 待复盘 · 候选 · 笔记书
│  ├─ 继续读
│  ├─ 待复盘
│  └─ 本地候选
└─ 阅读洞察
   ├─ 下周期建议
   └─ 阅读人格
```

推荐书籍默认从首页移除，保留发现页入口。若后续真实使用证明首页推荐有明确转化价值，再以条件化模块恢复。

### 9.2 已连接但无书架数据

```text
阅读总览
├─ 紧凑页头
├─ 今日阅读工作台
│  └─ 主动作：同步书架缓存
├─ 书架空状态
│  ├─ 当前没有本地书架缓存
│  └─ [同步书架]
└─ 必要连接与隐私说明
```

规则：

- 不展示大指标零值。
- 不展示最近阅读空列表。
- 不展示今日卡片的重复同步入口；今日卡片可隐藏。
- 不展示空的洞察和推荐区。
- 本地队列若无任何本地状态则隐藏。

### 9.3 未连接

```text
阅读工作台
把微信读书里的阅读记录整理成本机阅读资产。

[连接状态卡]
先保存 API Key
连接后可同步书架、笔记和统计。
[前往设置]
```

规则：

- 只保留一个设置主动作。
- 不展示四个不可完成的快捷入口。
- 不展示大指标和洞察。
- 若存在本地候选或本地状态，可在凭据引导后显示轻量本地队列，但不得与设置主动作竞争。

### 9.4 局部错误且有缓存

- 保留可用的主动作、最近阅读和队列。
- 错误只显示在对应模块。
- 最近阅读进度刷新失败不升级为整个总览失败。
- 阅读人格或推荐加载失败只隐藏或局部提示对应模块。
- 同步失败时保留旧缓存，不用骨架覆盖。

## 10. 详细设计

### 10.1 页头与 Hero 收口

#### P0 推荐

已连接状态移除 430px 大幅 Hero，改为紧凑页头：

```text
阅读工作台
今天读什么、整理什么、带走什么。

[同步书架] [查看书架]
```

视觉规则：

- 高度由内容自然撑开，不设置大面积固定高度。
- 不使用整幅背景图。
- 标题约 `1.625rem–1.875rem`。
- 说明不超过一行半。
- 同步为主操作或强调操作，查看书架为次操作。
- 笔记、复盘和发现继续由全局导航承接，不在页头重复四个入口。

#### 保守替代方案

若短期不删除 Hero，可先：

- 将最小高度从 430px 降到约 240–280px。
- 快捷入口从 4 个减为“查看书架”和“同步书架”。
- 三项大指标从右侧大卡片改为 Hero 下方轻量状态行。
- 保证 `DailyWorkbenchPanel` 在 900px 高窗口首屏可见。

P0 优先推荐直接改为紧凑页头，避免继续维护展示型 Hero 和工作台型首页之间的冲突。

### 10.2 今日阅读工作台

保留现有结构和数据模型：

```text
今日阅读工作台
今日最值得做                         深度 30 分钟

复盘《深度工作》
为什么现在做：已有笔记，尚未整理
完成后得到：行动清单、复盘问题和复盘文档
[开始复盘]

轻量 5 分钟：同步笔记
深度 30 分钟：打开阅读指南
```

调整规则：

- 继续只显示一个主动作。
- 备选动作最多两个。
- 删除后续 `today-actions-panel`。
- 主卡点击区域可以保留整卡按钮，但必须保持可读的焦点态。
- 无主动作时，提供一个明确恢复动作，不只展示说明文字。
- 主动作原因和结果不得固定高度截断。

### 10.3 删除辅助动作面板

删除：

```tsx
<article className="today-actions-panel" aria-label="今日可做">
  ...
</article>
```

同时清理：

- `.today-actions-panel`
- `.today-action-list`
- `.today-action-card`
- 只服务该面板的响应式规则

`todayActions` 数据仍保留，因为 `buildDailyWorkbenchActions(todayActions)` 继续使用它生成主动作和备选动作。

测试不再断言“辅助动作”存在，而应断言：

- 今日主卡只有一个。
- 备选动作不超过两个。
- 完整今日动作列表不存在。

### 10.4 最近阅读作为唯一主模块

保留 `WereadOverviewCard`，职责调整为：

- 展示最近 5 本电子书。
- 展示必要的书架和笔记规模上下文。
- 手动刷新最近 5 本的进度。
- 提供查看书架入口。
- 承接同步书架入口。

建议结构：

```text
最近阅读
最近 5 本电子书，按最后阅读时间排序

[同步书架] [刷新进度] [查看书架]

[书 1] [书 2] [书 3] [书 4] [书 5]
```

每本书只展示：

- 书封。
- 书名。
- 阅读进度或最近阅读时间。
- 累计时长可选，最多与进度并列展示两项元信息。

删除底部 `activity-panel`，包括：

- 第二套最近阅读列表。
- 重复书架分类。
- 重复同步书架和查看书架按钮。

数据函数 `getRecentEntries()` 若不再被其他业务使用，可在确认引用后删除；`getRecentOverviewEntries()` 继续保留。

### 10.5 今日卡片

保留 `DailyReadingCardPanel`，但调整为轻量内容段：

- 不再使用与主工作台同等级的完整大阴影卡片。
- 使用左侧细色条、分隔线或浅背景表达来源。
- 高度由内容决定。
- 只有一个入口。
- 位置在最近阅读之后、本地队列之前。

空态规则：

- 如果今日主动作已经是“同步书架”，今日卡片不再重复同一同步提示。
- 没有可消费内容时可隐藏，而不是必须生成空卡。
- 不展示伪划线、伪建议或心理判断。

### 10.6 本地进展并入队列

删除独立 `DashboardLocalProgressPanel` 大面板渲染，将其指标压缩为本地队列标题下的轻量摘要：

```text
本地阅读队列
已整理 3 · 待复盘 5 · 本地候选 4 · 笔记书 24

[继续读] [待复盘] [本地候选]
```

保留 `buildDashboardLocalProgress()` 作为纯函数，继续提供：

- 指标值。
- 重点提示。
- 空态判断。

但展示层调整为：

- `progress.metrics` 显示为可换行摘要项。
- `progress.highlight` 仅在有明确高价值信号时显示一行提示。
- 不再使用三栏布局和完整渐变背景。

如果本地队列完全为空：

- 显示一条紧凑空状态。
- 提供一个与当前状态匹配的动作。
- 不渲染三个等高空列。

### 10.7 阅读洞察

将“下周期建议”和“阅读人格”放入统一的阅读洞察区。

推荐布局：

```text
阅读洞察

[下周期建议：一条最值得执行的建议]    [阅读人格：简要状态]
```

规则：

- 下周期建议优先于阅读人格。
- 周期建议默认展示最多 1–2 条，不在首页展示完整报告。
- 阅读人格只显示代码、标签和一句摘要，完整维度进入阅读复盘或统计页。
- 保留“阅读风格隐喻，不代表真实心理人格”。
- 两个模块在窄屏下纵向排列。

### 10.8 推荐书籍

P0 推荐从首页移除 `dashboard-recommend-card`。

理由：

- 已有独立发现页。
- 推荐与“继续当前阅读、整理当前资产”的每日主循环关联较弱。
- 推荐卡会增加新书诱惑，可能与完成当前书和复盘现有笔记冲突。

保留：

- 页头或全局导航中的“发现”入口。
- 当用户没有最近阅读、没有候选、没有待复盘时，可以由今日主动作引导发现书籍。

不保留常驻首页推荐卡。

### 10.9 核心指标

当前三项大指标：

- 书架条目。
- 公开 / 私密。
- 最近同步。

不建议继续作为 118px 高的大数字卡片。

处理建议：

- `最近同步` 合并到页头或最近阅读操作区。
- `书架条目` 合并到最近阅读规模说明。
- `公开 / 私密` 下沉到书架页，不在首页常驻。

如果 P0 需要保守迁移，可先压缩为一行：

```text
书架 128 · 私密 4 · 最近同步 8 月 1 日
```

最终目标是删除独立 `metric-grid`。

### 10.10 连接状态

已连接状态不需要持续占据完整横向状态条。建议：

- 将“已连接”压缩为页头中的低调状态标记。
- 隐私说明放入 tooltip、设置页或首次连接成功反馈。
- 只有未连接、权限失效、升级要求或同步失败时才展示完整状态卡。

异常状态必须保持明确：

- 未连接：突出前往设置。
- 凭据失效：突出重新配置。
- 技能升级：突出升级和重试。
- 已连接正常：不与主动作竞争。

## 12. 视觉规范

### 12.1 内容宽度

- 总览内容区使用全局页面宽度，不额外引入超宽容器。
- 推荐最大可读宽度约 `1440px`。
- 主工作台和最近阅读可横跨内容区。
- 今日卡片、进展摘要和洞察不必都使用完整大表面。

### 12.2 间距节奏

使用现有 4px 基础单位：

- 页头到今日工作台：16–20px。
- 今日主卡内部关联元素：8–12px。
- 今日工作台到最近阅读：20–24px。
- 最近阅读到今日卡片：16–20px。
- 今日卡片到本地队列：20–24px。
- 队列到阅读洞察：24–32px。

规则：

- 同一模块内部使用紧密间距。
- 不同任务阶段使用更大分隔。
- 不让所有区段都固定为相同 18px gap。

### 12.3 卡片与边界

完整卡片只保留给：

- 今日主动作。
- 最近阅读中的可交互书目。
- 本地队列中的具体书目。

轻量区域使用：

- 分隔线。
- 浅背景。
- 左侧强调线。
- 文本分组。

禁止：

- 卡片内再嵌同权重卡片。
- 所有模块都使用渐变、阴影和圆角。
- 通过更强阴影解决信息层级。

### 12.4 排版

- 页标题：`1.625rem–1.875rem`。
- 今日主动作标题：`1.25rem–1.5rem`。
- 模块标题：`1rem–1.25rem`。
- 正文说明：`0.875rem–0.9375rem`，行高不低于 1.55。
- 辅助信息：不低于 `0.75rem`。
- 数字不再默认使用 `30–42px` 大号展示，除非是主动作必要证据。

### 12.5 色彩

- 使用现有 `--ink`、`--muted`、`--line`、`--green`、`--teal`、`--paper-rgb` 等变量。
- 绿色用于主动作、连接成功和可推进状态。
- 金色用于复盘或周期建议，但不大面积铺底。
- 蓝色用于候选或决策状态。
- 不用颜色单独表达状态，必须配合文字和结构。
- 深色主题不得硬编码浅色卡片背景。

### 12.6 动效

- 主卡、书目和队列 hover 位移不超过 1px。
- 颜色和边框过渡 120–180ms。
- 不对模块删除/插入做复杂布局动画。
- 同步图标继续使用旋转状态。
- 遵守 `prefers-reduced-motion`。

## 13. 响应式规则

### 13.1 宽屏桌面（≥ 1280px）

- 今日主动作横跨内容区。
- 最近阅读展示 4–5 个紧凑条目或两列紧凑列表。
- 本地队列保持三列。
- 阅读洞察两列。
- 首屏在 900px 高度内至少露出最近阅读标题或第一行内容。

### 13.2 中等窗口（980–1279px）

- 页头操作允许换行。
- 主动作详情保持可换行。
- 最近阅读两列或横向紧凑布局。
- 本地队列可保持三列，但低于合理最小宽度时切两列加一列换行。
- 阅读洞察两列或纵向排列。

### 13.3 窄窗口（< 980px）

- 所有主要区段单列。
- 主动作与备选动作纵向排列。
- 最近阅读使用单列紧凑列表或横向滚动固定宽度卡片。
- 队列三列改为纵向区段。
- 不隐藏同步、主动作、最近阅读入口和队列操作。

### 13.4 极窄窗口（< 640px）

- 页头按钮可等宽纵向排列。
- 主卡 reason/outcome 不截断。
- 进展摘要自然换行。
- 阅读洞察单列。
- 不显示纯装饰背景图。

### 13.5 紧凑密度

- 区段间距缩小约 20%。
- 不缩小主要按钮到难以点击。
- 不缩小正文到低于可读下限。
- 最近阅读和队列卡片内边距适度收紧。
- 今日主动作仍保持最高视觉权重。

## 14. 可访问性要求

- 页面根节点继续使用 `aria-label="阅读总览"`。
- 今日工作台继续使用 `aria-label="今日阅读工作台"`。
- 本地队列继续有明确区域标签。
- 主动作、最近阅读书目和队列书目必须支持键盘访问。
- 所有交互元素有清晰 `:focus-visible`。
- 同步和刷新状态使用 `aria-live="polite"` 或现有 toast/状态区域。
- 禁用状态不只依赖颜色。
- 装饰图片使用空 `alt`；若删除 Hero，则不新增替代装饰图。
- 200% 缩放时不得出现主按钮、原因或结果被截断。
- 页面结构中的标题层级应连续，不以视觉样式代替语义标题。

- 800×720 下无横向溢出。

### 18.3 视觉回归

重点关注：

- Hero 删除或降高后的首屏平衡。
- 今日主卡与最近阅读之间的节奏。
- 本地进展摘要合并后的队列标题高度。
- 深色主题下轻量分隔和背景对比度。
- 删除旧模块后是否出现意外大空白。

## 19. 风险与缓解

### 风险 1：删除完整动作列表后用户找不到低优先级动作

缓解：

- 主卡保留最多两个备选动作。
- 低优先级能力继续存在于全局导航和目标页面。
- 首页职责是帮助取舍，不是穷举全部能力。

### 风险 2：删除底部最近阅读后同步入口丢失

缓解：

- 在删除前先将 `onSync` 接入页头或 `WereadOverviewCard`。
- 增加 E2E 锁定同步、刷新进度和查看书架三个不同动作。

### 风险 3：Hero 收口后品牌感下降

缓解：

- 保留暖纸张色、品牌绿和克制排版。
- 将辨识度放在工作台结构和阅读语气上，而不是依赖大幅背景图。
- 可以保留小型书页纹理或局部图形，但不占据首屏主面积。

### 风险 4：本地进展并入队列后信息过密

缓解：

- 指标使用单行可换行摘要。
- 只展示四项固定指标。
- 高亮提示无明确价值时隐藏。
- 紧凑模式缩间距但不缩文字到不可读。

### 风险 5：移除推荐书籍降低发现能力曝光

缓解：

- 全局导航继续保留发现页。
- 没有最近阅读、候选和待复盘时，今日主动作可以引导发现。
- 真实使用数据证明需要后再条件化恢复，不常驻展示。

### 风险 6：旧 CSS 选择器被其他页面复用

缓解：

- 删除样式前使用内容搜索确认引用。
- 优先删除 `DashboardPage` 专用类。
- 通用 `.activity-panel`、`.metric-card` 等类不可直接全局删除，必要时只移除本页渲染或新增局部覆盖。

### 风险 7：测试依赖旧文案和模块顺序

缓解：

- 优先断言稳定语义区域和可用动作。
- 不为完整说明文案编写脆弱断言。
- 删除明确锁定“辅助动作”等废弃结构的断言。

## 23. 决策摘要

本轮最重要的四项裁决：

1. **今日动作只保留一套**：保留 `DailyWorkbenchPanel`，删除完整 `today-actions-panel`。
2. **最近阅读只保留一套**：保留 `WereadOverviewCard`，删除底部 `activity-panel`。
3. **进展摘要服务队列**：将本地进展并入本地队列，不再独占完整大面板。
4. **首页回到每日主循环**：压缩 Hero、指标和正常连接状态，下沉洞察，移除常驻推荐。

当前首页已经具备正确的动作模型、最近阅读数据和本地资产信号。下一步不需要继续新增能力，而应删除重复表达，让“今天做什么”真正成为页面结构和视觉上的唯一主叙事。
