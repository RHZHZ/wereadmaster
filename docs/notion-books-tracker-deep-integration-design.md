# Books Tracker 深度接入设计

## 1. 问题修正

此前“模板首页 + 独立阅读成果库”的方案只能让 wxreadmaster 把导出页面写入独立数据库。它不能让导入书籍出现在 Books Tracker 的 `Reading`、`To read`、`Completed`、`All Books` 等原生书架视图中。

对用户而言，这种接入只有视觉关联，没有数据关联，不满足“导入书籍直接展示在既有模板”的目标。

本设计将 Books Tracker by VPM 定义为首个专用模板适配器：

> 模板原有 Book Library 是书籍档案与书架视图的数据源；wxreadmaster 创建或更新书卡，并把完整笔记、复盘和阅读决策关联到独立的阅读成果库。

## 2. 设计结论

采用双库关系模型，而不是让 `阅读成果库` 替代模板书库：

```text
wxreadmaster 本地书籍 / AI 成果
        |
        +--> Books Tracker Book Library
        |      书名、作者、封面、状态、进度、Book ID
        |      驱动 Reading / To read / Completed / All Books 视图
        |
        +--> 阅读成果库
               笔记、书籍复盘、路线、统计复盘、选书决策全文
               Relation --> Book Library
```

`Database [Do Not Remove This]`、Kinds、原有分类、阅读目标及模板公式全部保留。应用不会把它们替换为自己的数据库。

## 3. 用户体验目标

- 从 wxreadmaster 导入一本书后，书卡直接出现在模板现有书架视图。
- 书卡显示模板原有的封面、标题、状态与进度，而不是另一套平行书架。
- 打开书卡可以看到关联的微信读书笔记、AI 复盘和其他阅读成果。
- 用户已有的评分、分类、手动备注和模板公式不被覆盖。
- 非书籍成果仍可独立存在，不强行绑定不存在的书卡。

## 4. 非目标

- 不支持任意第三方模板的自动字段猜测。
- 不改写 `Database [Do Not Remove This]` 的结构、公式、Kinds 或示例分类。
- 不做 Notion 与 wxreadmaster 的实时双向同步。
- 不自动迁移用户已经手工维护的所有书卡。
- 不将阅读路线拆成 Notion 任务系统。

## 5. 数据模型

### 5.1 Book Library：模板主书库

Books Tracker 的 Book Library 是模板中所有书架视图的唯一数据源。每本 wxreadmaster 书籍在其中最多一条书卡。

应用新增或复用下列字段。实际字段名称和类型必须在连接时探测，不依赖截图文字：

| 逻辑字段 | 作用 | 写入策略 |
| --- | --- | --- |
| `Title` | 书名 | 应用维护 |
| `Author` | 作者 | 应用维护 |
| `Cover` | 书架卡片封面或页面封面 | 应用维护 |
| `Status` | Reading / To read / Completed / Archived | 应用维护 |
| `Progress` | 阅读百分比 | 应用维护 |
| `wxreadmaster Book ID` | 幂等写入键 | 应用维护，模板专用新增字段 |
| `微信读书` | 原书链接 | 应用维护，字段存在时写入 |
| `Rating`、`Kinds`、标签、手动备注 | 用户的模板数据 | 不写入 |

字段名称可本地化，但映射一经确认后使用 Notion property ID 保存，避免用户改显示名称导致导入失效。

### 5.2 阅读成果库：完整成果档案

沿用当前 `阅读成果库`，每次导出创建一条成果页。增加或复用 Relation 属性：

| 字段 | 类型 | 作用 |
| --- | --- | --- |
| `关联书籍` | Relation -> Book Library | 将书籍笔记、书籍复盘等关联到模板书卡 |
| 其余现有字段 | 保持不变 | 资产类型、导出时间、行动数、正文等 |

书籍笔记和书籍复盘必须写入单本 Relation；阅读路线和选书决策可关联多个已识别的书籍；阅读统计复盘没有明确书籍时保持未关联。

## 6. 字段探测与连接

### 6.1 专用连接入口

Notion 设置页新增 `连接 Books Tracker 书架` 操作，替代“仅接入现有模板”的通用承诺。

用户流程：

1. 复制 Books Tracker by VPM 模板，并把模板首页共享给 Integration。
2. 在应用粘贴模板首页链接或 ID。
3. 应用在可访问页面中发现或让用户选择 `Book Library`。
4. 应用读取书库 schema，展示字段映射预览。
5. 用户确认后，应用创建/复用 `阅读成果库`，并新增 Relation 与 `wxreadmaster Book ID`。
6. 应用将书库和成果库 ID、字段 property ID 保存为模板配置。

### 6.2 发现与回退

发现逻辑按以下顺序执行：

1. 在模板首页的可访问数据库中匹配 Book Library 候选。
2. 候选唯一且包含标题字段时，预选该库。
3. 候选不唯一或字段无法验证时，让用户从发现的数据库列表中手动选择。
4. 找不到候选时停止，不创建任何书库；用户可以重新共享模板首页或选择现有数据库。

不能用 `Database [Do Not Remove This]` 的名称猜测 Book Library，也不能直接把它作为导出目标。

### 6.3 需要确认的外部改动

确认页面必须列出实际将执行的变更：

- 在 Book Library 新增 `wxreadmaster Book ID`（若缺失）。
- 在 `阅读成果库` 新增 `关联书籍` Relation（若缺失）。
- 后续导出会在 Book Library 创建或更新书卡。
- 模板原有书籍、Kinds、评分、分类、公式与视图不会删除或改写。

用户确认前只允许读取 schema，不得调用创建数据库、创建属性或创建页面接口。

## 7. 导入与更新规则

### 7.1 书籍 upsert

对每份具有真实 `bookId` 的书籍笔记或书籍复盘：

1. 用 `wxreadmaster Book ID` 查询 Book Library。
2. 找到书卡则更新应用维护字段。
3. 找不到书卡则创建一张新书卡。
4. 创建/更新成功后，向 `阅读成果库` 创建成果页并写入 Relation。

唯一键只使用真实微信读书 `bookId`，不使用书名或作者模糊匹配，避免同名书和不同版本错误合并。

### 7.2 状态和进度映射

| wxreadmaster 本地状态 | Books Tracker 状态 |
| --- | --- |
| 候选、想读 | To read |
| 在读 | Reading |
| 已读、完成 | Completed |
| 已归档 | Archived |
| 无法识别 | 不写 Status，保留模板默认值 |

进度以 0-100 Number 写入。模板状态选项名称不完全一致时，连接预览要求用户选择映射；无法安全映射时不写该字段。

### 7.3 封面策略

连接时探测书架卡片使用的封面来源：

- 若 Book Library 有用于 Gallery 的 Files/Media 封面字段，写入该字段。
- 否则写入 Notion Page Cover。
- 两种方式都不可用时，保留无封面书卡并提示，不阻断正文导出。

封面 URL 必须是 Notion 可访问的远程图片地址。应用不上传用户本机图片到第三方图床。

### 7.4 写入顺序与失败恢复

顺序固定为：`Book Library upsert -> 阅读成果库创建/关联 -> 正文 blocks`。

| 失败点 | 结果 | 恢复策略 |
| --- | --- | --- |
| 书卡 upsert 失败 | 不创建成果页 | 修复模板权限或字段映射后重试 |
| 成果页创建失败 | 可能已有书卡 | 下次导出按 Book ID 复用书卡，不创建重复书卡 |
| Relation 写入失败 | 成果页保留但未关联 | 返回明确 warning，不丢弃正文 |
| 封面写入失败 | 书卡/成果保留 | 返回 warning，不重试整次导出 |

不做自动网络重试，避免未知结果导致重复书卡或成果页。

## 8. 所有权与冲突边界

应用只维护其声明的字段：标题、作者、封面、状态、进度、Book ID 和微信读书链接。模板用户维护 Rating、Kinds、分类、备注及其他自定义字段。

首次连接成功后，设置页展示“应用维护字段”清单。用户若不接受 Status/Progress 由应用更新，可在字段映射预览中取消这两项；取消后模板视图仍可显示书卡，但状态和进度保持手工维护。

用户删除 `wxreadmaster Book ID` 或 Relation 后，后续导出退化为独立成果库写入，并显示“模板关联已失效”的恢复提示；不得按书名猜测或覆盖旧书卡。

## 9. 界面设计

设置页主路径改为：

```text
推荐模板：Books Tracker by VPM [复制模板]

Books Tracker 书架接入
  模板首页链接或 ID
  [分析模板]

  书库：Book Library
  字段映射预览
  书卡封面：Cover 属性 / Page Cover
  状态映射：Reading / To read / Completed / Archived
  应用维护字段：标题、作者、封面、状态、进度、Book ID
  [确认连接并创建关联]

基础工作台（折叠兜底）
```

`分析模板` 是只读操作。`确认连接并创建关联` 才会写入 Notion，需要二次确认。

连接完成后，成功区域显示：

- 已连接 Book Library。
- 已配置阅读成果库。
- 已关联/创建书卡数量。
- 打开模板首页、Book Library、阅读成果库三个入口。

## 10. 实施分期

### P0：Books Tracker 专用适配器

- 只支持 Books Tracker by VPM，不声称兼容任意模板。
- 只读分析模板与 Book Library schema。
- 用户确认后创建/复用成果库、Book ID 和 Relation。
- 书籍笔记与书籍复盘触发 Book Library upsert 和成果 Relation。
- 书卡封面、标题、作者、状态、进度按确认映射写入。
- 设置页展示连接状态与字段所有权。

### P1：更多成果关联

- 阅读路线和选书决策关联多本书。
- 提供模板状态/封面字段映射编辑。
- 提供已有手工书卡的显式匹配工具，不做自动模糊合并。

### 不做

- 自动分类到 Kinds。
- 自动创建或重写模板所有视图。
- 双向同步模板手工修改回 wxreadmaster。
- 支持未经验证的模板数据库结构。

## 11. 验收标准

- 导入一份有真实 `bookId` 的书籍笔记后，Book Library 只有一张对应书卡。
- 书卡出现在模板原生 `Reading`、`To read`、`Completed` 或 `All Books` 视图中，取决于状态映射。
- 同一本书再次导入不会创建重复书卡。
- 书籍复盘页能从 Relation 打开对应模板书卡，书卡也能查看关联成果。
- 用户在 Kinds、Rating、分类、备注中的内容不会被应用覆盖。
- 统计复盘仍可导出，即使没有关联书卡。
- 找不到 Book Library、字段不兼容或用户未确认时，不产生外部写入。
- 删除 Book ID 或 Relation 后，应用给出恢复提示，不按书名错误合并。

## 12. 设计原则

- KISS：只为一个已验证模板做一个适配器，不建立“万能模板解析器”。
- YAGNI：不处理自动分类、模板公式改造和双向同步。
- DRY：Book Library upsert 作为所有书籍成果共用步骤，成果正文继续复用现有 Notion 导出器。
- SOLID：模板分析、字段映射、书卡 upsert、成果导出和凭据管理分离职责。
